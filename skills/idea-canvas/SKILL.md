# 灵感画布整理

## 一句总纲

**整理是帮用户看清自己在想什么，不是替用户下结论。** 用户随手写下的每一条都是素材：可以归类、可以指出重复和矛盾、可以标出哪些是证据哪些是猜测，但不能删、不能改写原话、不能把猜测说成事实。

## 画布是什么

- 文件格式是开放的 JSON Canvas（`.canvas`），Obsidian 也能打开。格式要点见 [references/json-canvas.md](references/json-canvas.md)。
- 工作区级画布：`<工作区>/灵感画布/<名字>.canvas`；项目级画布：`<项目根目录>/灵感画布.canvas`。
- 节点四种：便签（`text`，随手的观点）、链接（`link`，文章、竞品、视频）、文档（`file`，一份 Markdown 或图片）、分组（`group`）。
- 拾阶的画布标签页会自动保存，也会在文件被改动后自动重新加载，所以你直接改文件，用户马上就能看到。

## 七步

1. **读画布。** 用户没说是哪张画布时，从对话里的路径找；还找不到就列出工作区里的 `.canvas` 文件让用户选。运行：

   ```bash
   python3 <本 skill 目录>/scripts/canvas_tool.py summary <画布.canvas> --workspace <工作区根目录>
   ```

   文档节点的全文用读文件工具读。图片节点能看就看，看不了就按文件名理解并在整理稿里说明。

2. **打开链接。** 每个链接节点用联网工具读一遍，记：标题、来源、3 行以内的要点、和画布上哪些点子有关。打不开的（需登录、失效）写「打不开」，不要猜内容。

3. **给每条素材定性。** 用立项的证据标签判断它是什么：【用户原话】（用户或身边人亲历）、【公开资料】（文章、报告）、【竞品】、【个人看法】、【AI 推断】（你推出来的）。同一件事有矛盾的说法，标出来。

4. **分主题。** 3–7 个主题，每个主题一句话说清楚它在说什么。常用的分法（按素材选，不要硬套）：
   - 问题（谁、在什么场景、卡在哪）
   - 用户（谁有这个问题）
   - 方案点子
   - 竞品与参考
   - 风险与疑问
   重复的点子放进同一个主题；一条素材只进一个主题。

5. **写回画布。** 写一个整理方案 JSON（格式见 `scripts/canvas_tool.py` 开头说明），然后：

   ```bash
   python3 <本 skill 目录>/scripts/canvas_tool.py apply <画布.canvas> <整理方案.json>
   ```

   - 每个主题一个分组，组里第一个节点是你写的主题小结（2–3 句，引用节点编号说依据）。
   - 最上面放一段总览：一共几条素材、几个主题、最值得往下走的一两个方向、最大的疑问。
   - 用户原来的分组想沿用就在方案里写 `reuse`；没沿用的分组会被去掉，第一次整理前的原样已经备份为 `<画布名>.整理前.canvas`。
   - 整理方案 JSON 写在系统临时目录，用完不留在工作区。

6. **写整理稿。** 照 [templates/整理稿.md](templates/整理稿.md) 写 `<画布名>-整理.md`，放在画布旁边。整理稿是后面立项、PRD 能直接引用的材料，每一条都要能追到画布上的节点编号或链接。

7. **问去向**（用提问工具，推荐项放第一个）：
   - **开新项目立项**：素材里能看出一个具体的问题和用户时推荐。交给 `aipm-hub` 新建项目，告诉它「立项材料：<整理稿路径>」，立项从「已有材料」起点开始。
   - **补进已有项目**：素材明显属于某个项目时推荐。说清补进哪个阶段哪一节（如「竞品与参考 → 立项 04 看清对手」「问题与用户 → PRD 需求背景」），由对应阶段的 skill 去改，你不直接改项目产出物。
   - **先放着**：素材还太散。告诉用户还缺什么（比如「点子很多，但没有一条是用户亲历的问题，建议找 3 个人聊聊」）。

## 不要做

- 删除、合并、改写用户的节点。重复的放在一起，在小结里说明。
- 把【个人看法】【AI 推断】写成事实。
- 打不开的链接编内容。
- 在用户没选去向之前改项目里的文件。
- 画布不在工作区里时写文件：告诉用户把画布放进工作区再整理。

## 风格

- 小结和总览用短句，引用节点编号（`n3`）方便用户在画布上找。
- 主题名 2–8 个字。
- 再次整理时，先读上一次的整理稿，说清这次多了什么、变了什么。
