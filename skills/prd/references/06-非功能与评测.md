# 第 06 站：非功能需求、评测需求与定稿

**写什么：** 第五节「非功能需求」、第六节「评测需求」，然后按 [自审清单.md](自审清单.md) 全文自审、定稿。

## 1. 非功能需求

表格三列：类别 / 描述 / 详情。**详情每条都要有数字或可验证的条件**，写成「名称：要求」：

| 类别 | 必写的点 | 详情示例 |
|---|---|---|
| 1. 性能 | 关键操作的响应时间、页面加载、并发 | 响应时间：点击「生成大纲」后 10 秒内展示；并发：支持 50 人同时生成 |
| 2. 可靠性 | 可用性、容错、数据完整 | 可用性：核心功能 99.9%（每月计划外停机 ≤ 45 分钟）；容错：单个模型实例超时自动重试或切备用，用户无感知 |
| 3. 安全性 | 认证、授权、数据保密、审计 | 认证：公司 SSO 登录；保密：静态加密存储，传输走 HTTPS；审计：上传、删除、权限变更都留操作人、时间、内容 |
| 4. 易用性 | 学习成本、操作效率、无障碍、一致性 | 学习成本：新用户无人引导 15 分钟内走完一遍完整流程；效率：相比原方式耗时减少 80% 以上 |
| 5. 兼容性 | 终端、浏览器、文件格式、设备 | 导出的 .docx 能被 Word 2016+、WPS、Google Docs 正常打开且格式不变 |
| 6. 可维护性 | 模块化、可配置 | 新增一个 Agent 不影响现有 Agent；报告模板（页眉、字体）后台可配，不写死在代码里 |
| 7. 成本 | 单次任务模型成本、月度预算、成本告警 | 单份报告模型调用成本 ≤ 3 元；月度预算 2000 元，到 80% 告警 |

- 第 7 条「成本」是 AI 产品必写的：没有成本上限，05 选模型时就没法取舍。用户说不出数字，就按「目标用户愿意付的钱 × 合理毛利」倒推一个，标【测算】。
- 和第四节交互里已经写的时延要一致；不一致以这里为准并回改。
- 第一版是内部试用的，可用性、并发可以写低，但要写，不能空着。

## 2. 评测需求

这一节回答：**上线前凭什么判断 AI 做得够好**。写一段话加几条规则，详细方案留给 05 模型评测阶段。

必须写清的六件事：

1. **谁来出题**：业务专家提供真实场景的问题并定义标准答案；产品和算法把它们工程化为可执行的评测用例，并分析结果驱动迭代。
2. **评测对象**：是整条链路（第 05 站的链路表），还是某一个环节。多环节产品要评整条链路，不能只评检索问答。
3. **题量和出处**：多少道题、只用哪个真实项目的资料、按环节和专项出题。没有真实资料的，写清用什么替代，并标【模拟】。
4. **通过规则**：每题跑几次、几次都过才算过（推荐「每题跑三次、三次都过才算过」，因为模型输出有随机性，一次过不代表稳定）。
5. **红线**：碰一次就判不过、不看别的分的错误。从链路表「最怕什么」一列和业务里「写错就是事故」的东西里挑，例如「本项目自己的投资、规模、技术路线写错」「编出资料里没有的文号或结论」。
6. **重跑规则**：提示词、模型、工具任何一项改动后，全部题目重跑；线上每出现一种新的坏例，加一道题。

示例：

> 上线前按评测集评估效果。评测集由产品和业务专家共同构建：专家提供真实工作中的问题并定义标准答案，产品把它们写成可执行的用例。评测对象是大纲、正文、审计、优化四个环节组成的整条链路，不只是检索问答。评测集 12 道题，只用本项目资料，按环节和专项出题，每题跑三次、三次都过才算过；本项目自己的投资、规模、压力、技术路线、工期写错即为红线。提示词、模型或工具任何一项改动后，12 道题全部重跑。评测方案和结果见 `05-模型评测/评测方案.md`。

## 3. 全文自审与定稿

按 [自审清单.md](自审清单.md) 逐条过。没过的条目当场改；改不了的（缺证据、等拍板）写进「附：假设与待定问题」，并在 `aipm.json` 记 `pending`。
