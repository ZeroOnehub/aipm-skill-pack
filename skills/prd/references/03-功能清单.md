# 第 03 站：功能清单

**写什么：** 第三节「功能清单」「本期不做」。
**回答的问题：** 这一版到底做哪些功能，每个做到什么程度算完成？

## 1. 从哪里来

- 立项的 `05-MVP范围表.md`：第一版做什么、不做什么。
- 原始用户流程的痛点步骤：每个 P0 功能都要能指向一个痛点步骤。
- 需求池里排进本期的条目。

先把候选功能按**用户任务的顺序**排（创建 → 生成 → 修改 → 产出 → 反馈），再分一级、二级。

## 2. 表怎么写

| 一级功能 | 二级功能 | 验收标准（单句） | 优先级 | 里程碑 | 完成日期 | 负责人 |
|---|---|---|---|---|---|---|
| 知识库 | 手动文档上传 | 支持批量上传 PDF、Word，单文件 ≤ 100MB，上传后自动解析、分块、向量化并显示「可用」 | P0 | M1 | | |
| 内容交互 | 内容溯源标注 | 点击高亮句弹出原文片段、文档名、页码，抽检溯源准确率 ≥ 95% | P0 | M1 | | |
| 内容交互 | 全局优化 | 一键统一术语 / 单位 / 风格并给出修订说明，耗时 ≤ 45s | P1 | M2 | | |

### 验收标准的写法

**一句话，测试拿着就能判对错。** 三种写法任选：

1. **可观察的结果**：「上传后文档出现在列表中并标记为可用」。
2. **数字门槛**：「3 秒内返回答案和引用文档」「格式错误率 = 0」。
3. **AI 质量门槛**：「抽检 20 份，事实性错误率 ≤ 18%（评审专家判）」。AI 质量门槛**必须写抽检量和谁来判**。

不合格的写法和改法：

| 不合格 | 改成 |
|---|---|
| 支持智能问答 | 侧边栏输入问题，3 秒内返回答案和引用文档 |
| 生成高质量大纲 | 生成至少三级结构的大纲，覆盖行业范本的全部必选章节，各章建议字数之和等于目标字数 |
| 体验流畅 | 删掉，放到第五节非功能需求里量化 |

### 优先级

| 级别 | 含义 | 判断 |
|---|---|---|
| P0 | 没有它核心闭环跑不通 | 去掉后用户还能完成核心任务吗？不能 → P0 |
| P1 | 本期要做，但可以晚于 P0 交付 | 去掉后能用但明显不好用 |
| P2 | 有余力再做 | 锦上添花 |

**P0 能串成一条闭环**：把 P0 按用户任务顺序念一遍，用户从进来到拿到结果不缺一步。缺了，要么补一个 P0，要么承认闭环里有一步靠人工（写进本期不做的说明里）。

### 里程碑

M1 = 核心闭环能跑（P0 主体），M2 = 体验补全（P1），M3 = 扩展。完成日期和负责人没定就空着，不要编。

## 3. 本期不做

把需求池里没排进本期、但用户或业务方提过的功能列出来，每条一句为什么不做、什么时候再看。这一节是给评审和研发「挡需求」用的，写得越具体越好。

## 自检

- [ ] 每个二级功能都有一句可判定的验收标准，AI 质量门槛写了抽检量和谁判
- [ ] P0 按顺序念一遍能串成闭环
- [ ] 每个 P0 都能指向原始流程里的一个痛点步骤
- [ ] 功能数量和立项的 MVP 范围一致；多出来的说明原因
- [ ] 「本期不做」列了被砍掉的需求和理由
- [ ] 采纳 / 拒绝反馈这类给北极星取数的功能在清单里
