# PRD 自审清单

定稿前逐条过。每条只有「过 / 没过」，没过写原因和改法。把结果写进 `00-PRD档案.md` 的进度表。

## 一致性（最常出错）

- [ ] 北极星公式里的分子、分母，能用第四节的埋点算出来
- [ ] 第三节每个功能，在第四节详细交互里都有对应行；反过来，交互里没有清单外的功能
- [ ] 状态图的状态名、交互说明里的状态文案、埋点事件名三处一致
- [ ] 链路表的每个环节都有提示词；每个提示词引用的变量都在全局上下文 JSON 里
- [ ] 提示词里提到的工具都在工具汇总表里
- [ ] 第五节性能要求和第四节交互里写的等待时间一致
- [ ] 第六节的红线能追到链路表「最怕什么」或业务事故
- [ ] 兜底策略覆盖了链路表每个「最怕什么」
- [ ] 名词解释覆盖全文所有自造术语和指标；全文同一个东西只用一个名字

## 可判定性

- [ ] 功能清单每条验收标准，测试拿着能判对错
- [ ] AI 质量门槛写了抽检量和谁来判
- [ ] 非功能每条有数字或可验证条件
- [ ] 兜底的触发条件有阈值或错误码

## 证据

- [ ] 背景、目标、画像里的事实带证据标签
- [ ] 标【AI 推断】【测算】【模拟】的结论，在待定问题里有验证计划
- [ ] 没有编造的数字：拿不准的写「待验证」或「待建基线」

## 范围

- [ ] P0 能串成闭环，每个 P0 指向一个痛点
- [ ] 本期不做的列了，和立项的 MVP 范围一致
- [ ] 角色权限覆盖删除、导出、管理类操作

## 可读性

- [ ] 没有「提升体验」「智能化」这类无法判定的句子
- [ ] 每张图下面有一句「这张图看什么」
- [ ] 文首相关文档表的链接都能打开（还没有的写了「待 0X 阶段」）
- [ ] 变更日志记到了当前版本
