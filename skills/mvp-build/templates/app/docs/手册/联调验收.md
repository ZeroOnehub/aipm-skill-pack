# 联调验收（阶段 4）

**产物：** `docs/阶段文档/验收报告.md`、`docs/拾阶/评测/结果/<时间>/`、证据包 `docs/evidence/阶段4/`
**目的：** 前后端都做完以后，用拾阶的评测集跑一遍真实链路，按 PRD 功能清单逐条对照，给出「能不能给用户试用」的结论。

## 1. 用评测集跑真实链路

拾阶 05 阶段在单个环节上用固定输入选了模型；这里要验证的是**整条链路在产品里**跑出来的结果。

1. 后端加一个只在开发环境打开的评测入口（环境变量 `EVAL_MODE=1` 时才注册），例如 `POST /api/_eval`：
   - 请求体：`{"id", "stage", "user", "vars"}`（就是评测集一道题）
   - 用 `vars` 和 `user` 构造这道题的输入，跑产品的**真实链路**（真实模型、真实检索、真实提示词）
   - 返回：`{"output": "最终产出文本", "tool_calls": [{"name": "工具名"}], "tokens_in", "tokens_out", "cost"}`
   - 不是所有题都适合走整条链路：环节级的题（如只考审计）调用对应环节的函数即可
2. 运行（评测集和脚本都由拾阶放在 `docs/拾阶/评测/`）：

   ```bash
   cd <app 绝对路径> && EVAL_MODE=1 <启动后端的命令> &
   python3 docs/拾阶/评测/run_eval.py docs/拾阶/评测/评测集 --app-url http://127.0.0.1:8000/api/_eval --runs 3 --out docs/拾阶/评测/结果/联调-$(date +%Y%m%d)
   ```

3. 和拾阶评测报告的选型结论比：同一道题在 05 阶段过、这里不过的，说明链路拼接出了问题（上下文没传对、检索参数和评测时不同、提示词渲染错了），逐题查。
4. **红线命中必须是 0**，否则结论只能是「不通过」。

评测入口上线前必须关掉（`EVAL_MODE` 不在线上环境设置），在验收报告里写明。

## 2. 按 PRD 功能清单逐条对照

| PRD 功能 | 优先级 | 验收标准 | 怎么验 | 结果 | 证据 |
|---|---|---|---|---|---|
| 一键生成大纲 | P0 | 三级大纲，各章字数之和 = 目标字数 | 评测 T01 | 过（3/3） | 结果/…/汇总.md |
| 内容溯源标注 | P0 | 点击高亮句弹出原文、文档名、页码 | 手动步骤 3 | 过 | 截图 溯源浮窗.png |

- 「怎么验」三选一：自动测试（写测试名）、评测题（写题号）、手动步骤（写进照着做清单）。
- 每个 P0 都要有结论；P1 没做的写「本期未做」并对应 PRD「本期不做」或决策台账。
- 用 `python3 docs/拾阶/scan_project.py . --expect docs/拾阶/architecture-features.json` 扫一遍，看技术方案选中的组件在代码里有没有落实（「没扫到」要打开代码确认，不等于没做）。

## 3. 非功能和兜底抽查

- **时延**：PRD 第五节写的关键操作，各测 5 次取中位数。
- **成本**：从模型调用日志算单次任务成本，和 PRD 上限、评测报告的测算比。
- **兜底**：PRD 第七节每一行，人为制造一次触发条件（断网、把超时调到 1 秒、让检索返回空、喂一个会让 JSON 解析失败的输出），看系统行为和用户看到的文案是否和 PRD 一致。
- **埋点**：走一遍主流程，检查 PRD 埋点表里的事件是否都上报了、字段齐不齐、北极星能不能算出来。
