# 前端风格选型（阶段 2）

**产物：** `docs/设计/风格候选.html`、`docs/设计/设计规范.md`
**目的：** 正式前端开工前，让产品经理从 3–4 个真实参考里挑定视觉方向，再把它写成设计规范。挑定之后才写正式前端，避免做完再推翻。

## 1. 先读输入

- `docs/拾阶/PRD.md`：用户是谁、在什么场景用（办公桌前长时间用、移动中快速用、给客户演示）、产品调性。
- `docs/拾阶/原型/`：页面清单和可点击原型。选一个**最能代表产品的 P0 页面**（通常是核心工作页，不是登录页）作为「代表页」。
- `docs/设计/` 里产品经理放的参考图、品牌色、Logo；原型档案里记的「视觉偏好」。

## 2. 上网找参考

用联网搜索和网页抓取工具找。按产品类型选来源：

| 来源 | 适合找什么 | 注意 |
|---|---|---|
| 同类真实产品（直接竞品、同行业 SaaS） | 用户已经习惯的布局和信息密度 | 最重要的一类，至少一个方向来自这里 |
| Refero（refero.design） | 真实产品的界面和风格，部分附 DESIGN.md | 能拿到 DESIGN.md 的，颜色、圆角、间距可直接转成设计变量 |
| Mobbin | 真实 App 和 Web 的页面截图 | 需要登录，拿不到就让产品经理截图发来 |
| Godly、Land-book、Lapa Ninja | 落地页、官网 | 只适合官网，不适合工作台类界面 |
| 开源设计系统：shadcn/ui、Radix Themes、Geist；面向国内 B 端的 Ant Design、Arco Design、TDesign | 成套的组件和设计变量 | 开源可商用的可以直接用它的变量 |
| Dribbble、Behance | 概念稿 | 好看但常常做不出来，只借配色和氛围 |

每个参考记：链接、截图（有浏览器工具就截，存进 `docs/设计/参考/`）、借鉴它的什么（配色 / 密度 / 布局 / 组件形状）。抓不到的页面（需登录、反爬）让产品经理截图发来。

**版权**：借鉴风格，不搬素材。别人的 Logo、插画、图片、文案不用；开源可商用的设计系统可以复用变量。

## 3. 定 3–4 个方向

方向之间要有**看得出的差别**，不要四个都是「蓝色简洁风」。常用的区分维度：

- 信息密度：紧凑（表格多、专业用户）↔ 宽松（新手、低频）
- 气质：克制专业 ↔ 温暖亲和 ↔ 鲜明有品牌感
- 明暗：浅色为主 / 深色为主
- 强调色：冷色 / 暖色 / 中性加一个高亮色

规则：至少一个「安全牌」贴近目标用户行业的习惯；至少一个和其他方向明显不同的；每个方向都要说清**为什么适合这个产品的用户和场景**。

每个方向提取一组设计变量：主色和中性色阶、成功 / 警告 / 错误色、**AI 内容的强调色**、字体与字号阶梯、圆角、间距密度、阴影、边框、图标风格。

## 4. 做风格候选页

把 `docs/设计/风格候选-模板.html` 复制成 `docs/设计/风格候选.html`，把代表页的真实内容（用原型里的假数据）填进去。**同一个代表页，用每个方向的变量各渲染一遍**，页面顶部切换方向。每个方向下面写：参考来源链接、借鉴了什么、适合的理由、可能的问题。

代表页里必须出现：主操作按钮、一段 AI 生成的内容（带 AI 标识和溯源入口）、一个加载或流式状态、一个错误提示、一张表格或列表。这样挑的时候能看到所有关键元素。

## 5. 请产品经理挑

告诉他打开 `docs/设计/风格候选.html` 切换着看，回答三件事：选哪个；哪里要改（颜色、密度、字体）；有没有要混搭的（「A 的配色 + B 的密度」）。最多改两轮，再多说明方向本身不对，回第 3 步换方向。

## 6. 写设计规范

`docs/设计/设计规范.md`，照 `docs/设计/设计规范-模板.md` 的结构：设计变量表、Tailwind `@theme` 代码块（正式前端直接用）、字体、组件规则、AI 专属样式（AI 内容标识、流式光标、溯源标签、反馈按钮、待补充标记）、各状态样式、禁止事项。

设计规范定了以后，正式前端只用规范里的变量，不在组件里写死颜色和尺寸。

## 是否表

阶段 2 是无代码阶段：第 2、3、4、5、6 项按 `verify.sh 阶段2` 的输出填（多为 N/A），第 1 项填「风格候选已做、产品经理已选定」，第 9、10 项照常。
