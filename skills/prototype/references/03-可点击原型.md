# 第 03 站：可点击原型

**产物：** `原型.html`（复制 [../templates/原型.html](../templates/原型.html) 后填写）
**回答的问题：** 用户从头走一遍顺不顺？每种情况下用户看到什么？

## 做法

1. **一页一个 `<section data-page="P03">`**，用 `data-go="P02"` 的元素跳转（模板已处理，地址栏会变成 `#P02`，可以直接分享某一页）。
2. **主流程先通**：从首页点到拿到结果，一步不断。分支流程（编辑、导出、设置）后补。
3. **状态可切换**：页面里每个有多种状态的区域用 `data-states="空,生成中,完成,失败"` 包起来，里面每个状态一个 `data-state="生成中"` 的子块。模板右下角的状态面板会自动列出当前页的所有状态区域，点一下切换，方便评审时一个个看。
4. **AI 过程要演出来**：流式输出、分章节进度、生成失败，都用模板的 `fakeStream(el, text)`、`fakeProgress(el, steps)` 演示，不要只放一张「完成」的静态图。哪些状态必须有见 [AI交互状态.md](AI交互状态.md)。
5. **文案用 PRD 原文**：提示语、兜底话术、按钮名和 PRD 第四、七节一致。PRD 里没写的文案你先写，在走查记录里列出来让 PRD 补上。
6. **假数据像真的**：至少一条超长的、一条空字段的、一条带特殊情况的（比如报告标题 40 个字、某章资料为空标「待补充」）。

## 不要做的

- 不做真实的接口调用、登录、存储。
- 不引入任何外部库；交互用模板里的几十行原生 JS。
- 不做视觉风格：模板的中性样式就是终稿样式。

## 关卡

- [ ] 主流程从首页点到结果不断，每页都能返回
- [ ] 页面清单里每页的每个状态都能在状态面板里切到
- [ ] AI 的等待、流式、失败、兜底都演示了
- [ ] 文案和 PRD 一致，PRD 没写的已记下
- [ ] 用户亲手点过一遍
