# 第 04 站：走查回写

**产物：** `原型走查记录.md`；PRD 升小版本
**回答的问题：** 原型和 PRD 对得上吗？画的过程中发现了 PRD 的哪些漏洞？

## 1. 逐条走查

拿 PRD 功能清单逐条对照原型，写一张表：

| PRD 二级功能 | 验收标准 | 原型页 | 能演示吗 | 发现 |
|---|---|---|---|---|
| 一键生成大纲 | 生成三级大纲，各章字数之和 = 目标字数 | P03 | 能 | PRD 没写大纲生成后能不能单章重新生成 |

「能演示吗」三种：能 / 部分（缺某个状态）/ 不能（PRD 写了但原型画不出来，说明交互没想清）。

再按 [AI交互状态.md](AI交互状态.md) 过一遍每个 AI 功能，缺的状态列出来。

## 2. 发现分三类，各有去处

| 类型 | 例子 | 去处 |
|---|---|---|
| PRD 漏写 | 交互里没写的状态、文案、异常 | 直接补进 PRD，升小版本 |
| 要用户拍板 | 两种交互都说得通，影响范围或工作量 | 决策卡给用户（问题、选项、推荐、不选的后果），`aipm.json` 记 `decision` |
| 留给后面 | 视觉、动效、品牌感 | 写进 `原型档案.md` 的「留给 MVP」一栏 |

## 3. 回写 PRD

按 prd skill 的「升版」规则（旧版存进 `02-PRD/历史/`，升小版本，写变更日志）：

1. 详细交互设计表的「原型图」列，填上页面编号和文件，如「P03（`03-原型交互/原型.html#P03`）」。
2. 文首相关文档表的「原型」一行填上链接。
3. 补上第 1 步发现的漏写项。
4. 变更日志写「原型走查回写：补 x 处交互、y 处文案」。

## 4. 写走查记录

`原型走查记录.md`：走查表、AI 状态检查结果、发现与去处、PRD 改了哪几处、待拍板的事。

- [ ] 每个 AI 功能的状态检查过
