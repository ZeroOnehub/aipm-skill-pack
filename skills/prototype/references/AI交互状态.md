# AI 交互状态清单

AI 功能和普通功能最大的区别：**结果不确定、要等、会错**。原型要把这些情况都摆出来，评审才看得出兜底够不够。

## 每个 AI 功能逐项过

| 状态 | 什么时候出现 | 原型里要画什么 | 对应 PRD |
|---|---|---|---|
| 待触发 | 还没开始 | 触发按钮、输入区；有前置条件的写清缺什么（如「先上传至少 1 份资料」） | 详细交互「入口」 |
| 等待 | 已提交，首个结果还没回来 | 加载态和文案；超过阈值时的「比较慢，请稍候」 | 非功能「性能」 |
| 流式输出中 | 内容一段段出来 | 逐字或逐段出现；可「停止生成」 | 详细交互「交互」 |
| 分步进度 | 多环节链路 | 「正在生成：第四章 技术方案（4/13）」这类进度 | 系统处理流程 |
| 部分完成 | 一部分成功、一部分失败或缺资料 | 成功部分正常显示，失败部分标出并给单独重试；缺资料处显示「[待补充：……]」 | 兜底策略 |
| 完成 | 结果可用 | 结果、AI 内容标识、溯源入口、采纳 / 拒绝反馈 | 功能清单、埋点 |
| 待用户确认 | 链路中需要人拍板的一步 | 确认卡片：要确认什么、为什么、确认 / 修改 / 取消 | 全局上下文「事实基座」 |
| 失败 | 超时、报错、输出不合规 | PRD 兜底策略里的提示原文 + 重试按钮；已有内容不丢 | 兜底策略 |
| 被拒答 | 越界、敏感、超出能力 | 固定话术 + 告诉用户能做什么 | 兜底策略 |
| 低置信 / 没找到依据 | 检索分数低、资料不足 | 提示「未找到匹配资料」，给选择：用通用知识写（并标注）/ 补充资料 | 兜底策略 |
| 编辑后 | 用户改了 AI 的结果 | 改动标识；重新生成会不会覆盖用户的修改（要有提示） | 详细交互 |

## 三个常被漏掉的

1. **AI 结果和用户内容混在一起时怎么区分**：高亮、角标、颜色条，至少一种。
2. **重新生成会不会冲掉用户改过的部分**：要么局部重生成，要么先提示。
3. **反馈入口**：采纳 / 拒绝、点赞 / 点踩、标记错误类型。没有它，北极星和评测都拿不到数据。
