# 第 02 站：候选模型调研

**产物：** `候选模型表.md`（模板 [../templates/候选模型表.md](../templates/候选模型表.md)）
**回答的问题：** 哪几个模型值得放进评测？

## 1. 先写能力要求

从技术方案第 4 节和 PRD 抄出每个环节的能力要求，逐项写成可查证的条件：

| 能力 | 怎么写成条件 | 例子 |
|---|---|---|
| 中文质量 | 领域、文体 | 中文长篇专业报告写作 |
| 上下文长度 | 单次最大输入 token【测算】 | 单章输入约 30k token（资料 + 摘要 + 提示词） |
| 结构化输出 | 是否需要 JSON 模式 / 结构化输出 | 大纲必须是合法 JSON |
| 工具调用 | 是否需要 function calling、并行调用 | 正文环节要调检索工具 |
| 多模态 | 图片、文档、语音 | 无 |
| 时延 | 首字时间、总时长上限（PRD 第五节） | 大纲 10 秒内 |
| 成本 | 单次任务上限（PRD 第五节）倒推每环节单价上限 | 单份报告 ≤ 3 元 |
| 合规 | 数据能否出境、是否要境内备案模型、是否允许厂商用数据训练 | 企业资料不出境 |
| 部署 | 云 API / 私有化 | 云 API |

**合规和部署是硬条件，先筛**：不满足的模型不进候选，不管多强。

## 2. 上网查，查官方

用联网工具查，**以厂商官方文档和价格页为准**：

- 国内常见入口：DeepSeek 开放平台、阿里云百炼（通义千问）、智谱开放平台（GLM）、月之暗面（Kimi）、火山方舟（豆包）、腾讯混元、百度千帆（文心）、MiniMax。
- 海外常见入口：OpenAI、Anthropic（Claude）、Google（Gemini）。只在合规允许出境时考虑。
- 公开榜单（LMArena、Artificial Analysis、SuperCLUE、OpenCompass 等）只当线索：用来发现新模型、粗看相对强弱，**不当选型依据**，表里标【公开资料·榜单】。

这份名单只是起点，模型和价格变得很快：查到的每一个数（价格、上下文长度、是否支持工具调用）都要写**来源链接和查询日期**；查不到的写「未查到」，不要凭记忆填。

每个模型记：

- 模型名（接口里实际填的那个字符串）、厂商、接口地址（是否 OpenAI 兼容）
- 上下文长度、最大输出长度
- 输入 / 输出单价（元或美元每百万 token；有缓存价的也记），换算成人民币时写汇率和日期
- 结构化输出、工具调用、流式是否支持
- 限流（每分钟请求数 / token 数）、数据政策（是否用于训练、数据存放地）

## 3. 选 3–5 个候选

每个环节的候选至少覆盖三类：

| 类 | 作用 |
|---|---|
| 强 | 能力上限，回答「最好能做到多好」 |
| 省 | 便宜快的，回答「便宜的够不够用」 |
| 合规 / 备选 | 满足境内或私有化要求、或作为主模型挂了时的备用 |

再加一条：**审计、评审这类检查环节，候选里要有和生成环节不同厂商的模型**，避免同一种盲点。

## 4. 粗算成本

每个候选按技术方案第 10 节的 token 量算单次任务成本，超过 PRD 上限两倍的直接淘汰（写原因）。

## 关卡

- [ ] 能力要求写成了可查证的条件，合规和部署先筛过
- [ ] 每个数据有来源链接和查询日期，没有凭记忆填的
- [ ] 每个环节 3–5 个候选，覆盖强、省、合规三类
- [ ] 检查类环节有不同厂商的候选
- [ ] 粗算了成本，淘汰的写了原因
