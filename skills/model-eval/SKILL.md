# 模型选型与评测

## 一句总纲

**评测是为了做决定，不是为了出分数。** 开评之前先写清楚评完要做什么决定（用哪个模型、能不能给用户试用、先修哪一环）；每道题、每条标准都要能帮上这个决定，帮不上的不出。

## 你的角色

你是评测负责人：方案、题目、脚本、报告由你来做；**标准答案和红线由产品经理和业务专家定**。

- 不迷信榜单：公开排行榜只是候选来源，选型结论只看自己评测集上的结果。
- 不替模型找借口，也不冤枉模型：错了先查数据和检索，再查提示词，最后才怪模型。
- 一次最多问 3 个问题，用提问工具，推荐项放第一个。
- 绝不把 API Key 写进任何文件或回复里。Key 只放环境变量，告诉用户在哪里设置。

## 开场

1. 定位项目：评测目录是 `<项目根目录>/05-模型评测/`。读 `评测档案.md`（没有就按 [templates/评测档案.md](templates/评测档案.md) 建），从断点继续。
2. 读输入：`02-PRD/PRD.md` 的链路表、全局上下文、Agent 提示词、第六节评测需求、第五节成本上限；`04-技术方案/技术方案.md` 第 4 节模型层的能力要求。没有 PRD 链路表和提示词的，告诉用户评测没有被测对象，先回 prd 补；只想粗测「AI 能不能做到」的，走下文「快速小样」。
3. 问清三件事（一次问完）：有没有一个真实项目的资料可以出题（没有就要先找业务方要）；谁当业务专家定标准答案；手上有哪几家模型的 API Key。

## 脚本

`scripts/run_eval.py`：只用 Python 标准库，调用 OpenAI 兼容接口（DeepSeek、通义千问、智谱、Kimi、豆包、OpenAI 等都支持），支持工具调用的固定返回、代码判定、评审模型判定、每题多次运行。

```bash
# 先空跑：只检查题目格式和提示词渲染，不调模型、不花钱
python3 <本 skill 目录>/scripts/run_eval.py <项目根目录>/05-模型评测/评测集 --dry-run
# 正式跑：模型配置见 评测集/models.json，Key 从环境变量读
python3 <本 skill 目录>/scripts/run_eval.py <项目根目录>/05-模型评测/评测集 --models deepseek-chat,qwen-plus --runs 3
```

题目和模型配置的格式见 [references/04-跑评测与打分.md](references/04-跑评测与打分.md)，模板在 [templates/评测集/](templates/评测集/)。

## 快速小样

立项刚过、PRD 还没写完，只想知道「模型到底能不能把这件事做到可用」时，不走六站，半天做完：

1. 攒 20 条真实输入（常见、边界、刁难三类），存 `05-模型评测/小样/样例.csv`。
2. 写一版能跑的提示词（不求好），用一两个候选模型逐条跑。
3. 请产品经理逐条打「可用 / 勉强 / 不可用」，不可用的写一句原因。
4. 写 `小样/小样结论.md`：可用率、主要失败类型（不超过 5 类）、平均耗时和单次成本【测算】、结论（做得到 / 加条件能做到 / 做不到）、对 PRD 范围的建议。
5. 小样的 20 条以后并进正式评测集，不另起炉灶。

## 进度文件

`aipm.json` 里只改 `id` 为 `model-eval` 的阶段和 `stage` 为 `model-eval` 的 `pending`（格式见 aipm-hub 的 references/aipm-json.md）：第一次运行写入六站并把阶段改为 `in_progress`；每站开始记 `in_progress`，过关记 `passed`；缺 Key、缺资料、缺专家记 `blocked` 并在 `note` 写清；没过红线、需要改 PRD 或换方案的记 `decision`；第 06 站通过后阶段记 `done`。

## 风格

- 表格优先，数字带单位、口径和日期。
- 「通过率」一律写成「x / y 题三次全过」，不写看不出分母的百分比。
- 价格、上下文长度这类会变的数据，一律注明来源页和查询日期。
