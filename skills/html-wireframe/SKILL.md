# HTML 线框图

> 改编自 [plannotator/effective-html](https://github.com/plannotator/effective-html) 的 `html-wireframe`（MIT，plannotator）。改动：中文化；去掉「只能被显式调用」的限制，中文需求也能触发；去掉对仓库内其他 skill 的依赖；产出物默认存进拾阶的原型目录。

把一个产品问题变成一份好看懂、好改、好讨论的低保真 HTML。线框图要帮评审的人决定「屏幕上该有什么、任务该怎么走」，它不应该看起来像成品。

## 先定评审问题

动手前先读对话、需求说明和项目里的相关材料（在拾阶里，先读 `02-PRD/PRD.md` 的用户故事、功能清单和主流程）。沿用项目已有的术语、内容模型和产品约束。

依据的优先级：
1. 用户明确的指示和已接受的决定；
2. 产品现有的结构和术语；
3. 被建模的用户、任务和内容；
4. 你自己的布局判断。

动手前想清楚：
- 用户是谁，要完成什么任务；
- 评审的是哪一屏或哪一段流程；
- 必须包含哪些信息和操作；
- 哪些假设可以放心做；
- 这份线框图要帮大家回答哪些结构问题。

用真实的标签和有代表性的内容。低保真不等于可以用空白方块和乱码占位，文字会影响布局的地方就写真文字。

## 先探索结构，后谈样式

布局还没定时，做 2～3 个**真正不同**的方向，差异落在产品决策上，例如：
- 导航模型；
- 分组和顺序；
- 主操作放在哪；
- 信息密度；
- 总览式 还是 分步式；
- 桌面到手机怎么重排。

换个颜色、挪一下卡片不算不同方向。每个方向起一个短名，配一句话说清取舍。

方便的话把几个方向放在同一个 HTML 里，用一个小的、键盘可操作的切换器对比，不用开好几个文件。各方向的核心内容和任务保持一致。用户已经选定结构时，只做那一个。

## 故意做得不完成

- 克制的灰阶、系统字体、普通边框、简单色块。
- 不用品牌色、渐变、阴影、插画和装饰图片，不做精致的组件样式。
- 圆角和间距适度：足够判断层级，又不至于精致到让人开始评审品牌。
- 图片和富媒体用带标签的占位块，除非素材本身影响结构决策。
- 只在需要暴露假设、未决问题或画不出来的行为时加批注。

「故意不完成」不等于随便：间距乱、字看不清、响应式坏掉都不行。

## 只加有用的交互

点击跳转能帮助检验导航、展开收起或短流程时才加，保持即时、朴素：
- 评审范围内的链接、标签页、下一步 / 返回要能用；
- 用原生控件，键盘焦点可见；
- 不做复杂动画、数据持久化、模拟接口和生产级状态管理；
- 没有评审意义的控件删掉，或者明确标「不在本次范围」。

## 交付约定

- 一个自包含的 `.html` 文件，必要的 CSS 和 JS 都内联。
- 不需要构建工具，不依赖外部服务。
- 用语义化的地标、标题、列表、表单和按钮。
- 宽屏桌面和窄屏手机下都好用，页面不出现意外的横向滚动。
- 尊重原始材料，不为了填满空间编造额外的产品范围。

## 检查和交接

分别在桌面宽度和手机宽度打开检查：阅读顺序、换行、溢出、焦点可见、每条实现了的点击路径；确认几个方向在两种宽度下仍然结构不同。没有浏览器工具时，说清哪些检查没做，不拿读源码代替。

交接时给出：文件的绝对路径、各方向的名字和取舍、刻意留到高保真阶段再定的视觉决定。

## 产出位置

在拾阶里存到当前项目的 `03-原型交互/`，文件名如 `线框图-<页面或流程>.html`。
