# 老格式项目升级到新流程

`aipm.json` 没有 `version` 或 `version` 是 `1` 的项目，用的是老的六阶段：立项、PRD、原型交互、AI 方案设计、评测、上线复盘。新流程是：立项、PRD、原型交互、技术方案、模型选型与评测、MVP。

## 跟用户怎么说

一段话说清，然后用提问工具问（推荐项放第一个）：

> 这个项目用的是老流程。新流程把「AI 方案设计」换成了「技术方案」，「评测」换成了「模型选型与评测」，最后一步从「上线复盘」改成「做出 MVP」。立项、PRD、原型三个阶段的东西原样保留；老的 AI 方案设计、评测、上线复盘材料会搬进新目录下的「旧版-」文件夹，一个文件都不删，可以当新节点的输入。

选项：

1. 升级到新流程（推荐）
2. 先不升级，按老流程看进度

## 升级

先空跑给用户看要做什么，用户确认后再正式跑：

```bash
python3 <本 skill 目录>/scripts/migrate_v1.py <项目根目录> --dry-run
python3 <本 skill 目录>/scripts/migrate_v1.py <项目根目录>
```

跑完告诉用户：

- 哪些材料搬到了哪里；
- PRD 是按老标准写的，新的 `prd` skill 标准更细（需求背景维度表、四层目标、详细交互、全局上下文、Agent 提示词、兜底），建议走一次 PRD 升版，补齐后再进技术方案；
- 有老的开发文件夹的，项目面板照旧显示它的进度（按老的研发阶段名）；以后做新的 MVP 时用 `mvp-build` 建新的代码仓库，老的开发文件夹不受影响。

## 不升级

- 按老阶段汇报进度。
- 用户要做某件事时，照新节点的 skill 做，产出物放进老目录里对应的位置：技术方案放 `04-AI方案设计/`，模型评测放 `05-评测/`。
- 每次打开这个项目时不再追问，除非用户自己提起。
