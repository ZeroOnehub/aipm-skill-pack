# 生成合成测试数据

> 改编自 [hamelsmu/evals-skills](https://github.com/hamelsmu/evals-skills) 的 `generate-synthetic-data`（MIT，Hamel Husain）。改动：中文化；示例改成中文场景；名字统一加 `eval-` 前缀；产出物默认存进 AIPM 工坊的评测目录。

生成多样、真实、能覆盖失败空间的测试输入。

## 前提

生成之前先想清楚系统可能在哪里出错：问用户已知的易错点，看已有的用户反馈，或从现有轨迹里提出假设。第 1 步的维度必须瞄准预期的失败，不是随便变化。在 AIPM 工坊里，先读 `02-PRD/PRD.md` 的「评测样例」和「AI 能力边界」。

## 流程

### 第 1 步：定维度

维度是这个产品特有的变化轴，按「预计会在哪里出错」来选。

```
维度 1：[名字] —— [它刻画什么]
  取值：[值a, 值b, 值c, ...]

维度 2：[名字] —— [它刻画什么]
  取值：[值a, 值b, 值c, ...]

维度 3：[名字] —— [它刻画什么]
  取值：[值a, 值b, 值c, ...]
```

例：一个房产经纪助手

```
功能：用户想做什么
  取值：[找房, 约看房, 写邮件]

客户类型：为谁服务
  取值：[首次购房者, 投资客, 高端买家]

场景类型：问题清不清楚
  取值：[说得很清楚, 含糊, 超出范围]
```

先用 3 个维度。只有初步轨迹显示出新的失败方向时再加。

### 第 2 步：和用户一起写 20 个组合

一个组合（tuple）就是一组维度取值，定义一个具体的测试场景。把 20 个草稿组合给用户看，反复修改到用户确认它们是真实会发生的场景。这一步离不开用户的业务知识：哪些组合真会出现、哪些不现实，只有他知道。

```
(功能：找房, 客户：投资客, 场景：含糊)
(功能：约看房, 客户：首次购房者, 场景：说得很清楚)
(功能：写邮件, 客户：高端买家, 场景：超出范围)
```

### 第 3 步：让大模型扩充组合

```
为一个{你的产品描述}随机生成 10 个 ({维度1}, {维度2}, {维度3}) 的组合。

各维度：
{维度1}：{说明}。可选值：{取值}
{维度2}：{说明}。可选值：{取值}
{维度3}：{说明}。可选值：{取值}

每个组合按 ({维度1}, {维度2}, {维度3}) 格式输出。
不要重复，各维度的取值要有变化。
```

### 第 4 步：把每个组合改写成自然语言问题

用**单独一个**提示词做这一步。组合和问题一步生成，措辞会很重复。

```
我们在为一个{你的产品}生成模拟的用户提问。
{一句话说明它做什么}

已知：
{维度1}：{取值}
{维度2}：{取值}
{维度3}：{取值}

写一条用户可能真的会输入的问题，要体现上面的客户类型和场景特点。

示例：「{你手写的一条示例}」

现在生成一条新的。
```

### 第 5 步：过滤质量

逐条看，遇到下面情况就丢掉重写：
- 措辞别扭、不像真人
- 内容和组合的意图对不上
- 和其他问题太像

可选：让大模型按 1～5 分打「真实度」，低于 3 分的丢掉。

### 第 6 步：跑完整条流程

所有问题都跑一遍完整流程，记下完整轨迹：输入、每个中间步骤、工具调用、检索文档、最终输出。

**目标约 100 条高质量、多样的轨迹。** 这是达到饱和（新轨迹不再暴露新失败类别）的经验值，具体看系统复杂度。之后交给 `eval-error-analysis`。

## 抽样真实数据

有真实问题时，别随机抽，用分层抽样：
1. **找变化大的维度**：读一遍问题，找出它们的差异（长度、话题、复杂度、有没有约束条件）。
2. **打标签**：量小就和用户一起打；量大就对问题的 embedding 做 K-means 聚类。
3. **每组都抽**：保证各类问题都覆盖到，不只是最常见的那类。

真实和合成都有时，用合成数据补真实数据里偏少的类型。

## 反模式

- **不讲结构地生成。** 直接说「给我一些测试问题」，只会得到泛泛、重复、一路顺风的例子。
- **一步生成。** 组合和问题一起生成，多样性比分两步差。
- **随便定维度。** 不瞄准易错区域的维度，浪费测试预算。
- **跳过用户审组合。** 用户没先确认组合，就没法判断大模型生成的组合真不真实。
- **没人能判断真实度时用合成数据。** 那就用真实数据。
- **复杂的专业内容用合成数据**（法律文书、病历），大模型抓不住结构细节。
- **小语种或方言用合成数据**，生成的样本不真实。
