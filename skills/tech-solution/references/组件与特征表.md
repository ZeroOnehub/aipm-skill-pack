# 组件与特征表

## 14 个特征问题

技术方案第 2 节的特征表写好后，用 `scripts/features_from_md.py 04-技术方案/技术方案.md -o 04-技术方案/architecture-features.json` 直接转换，不要重新判。大白话版的问法见 [Agent特征快问.md](Agent特征快问.md)。

写进 `architecture-features.json`，键必须是下表的特征 id，不要用组件编号作键：

```json
{
  "destructive_ops": { "value": "no", "evidence": "只读推荐，不写外部系统（PRD §9）" },
  "audit_needed": { "value": "yes", "evidence": "酒类合规要拦截拒答（PRD §7）" }
}
```

| 特征 id | 问题 | 触发组件 |
|---|---|---|
| `destructive_ops` | 是否涉及破坏性或敏感操作（删除、写入外部系统、支付、发送消息、隐私数据）？ | s03 权限系统 |
| `audit_needed` | 是否需要审计、拦截、埋点、合规记录？ | s04 钩子系统 |
| `multi_step` | 单次交付是否需要先列计划再逐步推进并跟踪进度？固定顺序调用几个工具不算 | s05 任务规划 |
| `context_heavy` | 是否会出现上下文爆炸的子任务，或可并行的探索型子任务？ | s06 子 Agent |
| `large_knowledge` | 领域知识库是否庞大、需要按需加载？ | s07 技能加载 |
| `long_sessions` | 会话是否很长、工具输出或日志量是否很大？ | s08 上下文压缩 |
| `cross_session_memory` | 是否需要跨会话记住用户偏好、决策、历史？ | s09 记忆系统 |
| `persistent_goals` | 目标是否需要持久化、支持断点续跑？ | s10 任务系统 |
| `slow_operations` | 是否有耗时几分钟以上的慢操作需要不阻塞主流程？ | s11 后台任务 |
| `scheduled` | 是否需要定时自动触发？ | s12 定时调度 |
| `parallel_isolated` | 是否需要多任务并行且各自隔离工作区？ | s13 Agent 团队 |
| `external_ecosystem` | 是否需要接入外部工具生态（MCP、第三方插件）？ | s14 MCP 插件 |
| `fixed_orchestration` | 流程是否是固定阶段序列，且各阶段无需模型临场决策？ | s16 工作流运行时 |
| `auto_completion` | 是否需要自动判断「何时算完成」（独立评估器）？ | s17 目标闭环 |

## 选型规则

- s01 Agent Loop、s02 工具系统恒选。
- 每个特征：`yes` → 必选，`later` → 二期，`unknown` → 待确认，`no` → 放弃。
- s15 集成 Harness：除 s01、s02 外第一版必选的组件达到 3 个则必选；算上二期达到 3 个则二期；否则放弃。

## 17 个组件

每个组件的详细说明和可运行的最小实现在 [components/](components/)（`sNN_*/README.md` 和 `code.py`）。06 MVP 的安装脚本按选型把「必选」组件复制进 `app/参考组件/`，给写代码的 AI 参考。

| 域 | 组件 | 解决什么 | 生产级要点 |
|---|---|---|---|
| 行动 | s01 Agent Loop | 最小可运行闭环：消息 → 模型 → 工具 → 结果 → 循环 | 重试、超时、token 上限、停止原因完整处理 |
| 行动 | s02 工具系统 | 循环不变，工具可增 | 参数 schema 严格、参数校验、错误回传格式统一 |

| 约束 | s03 权限系统 | 先划边界，再给自由 | 白名单/黑名单、破坏性操作二次确认、审计日志、默认拒绝 |
| 约束 | s04 钩子系统 | 在工具调用前后挂审核、拦截、埋点 | 调用前可阻断、调用后可观察、异常不影响主循环 |
| 认知 | s05 任务规划 | 先计划后执行 | 计划持久化、状态流转、进度可查询 |
| 认知 | s07 技能加载 | 领域知识按需加载 | 目录先行、按需展开、版本管理 |
| 认知 | s09 记忆系统 | 跨会话记住该记的 | 筛选 → 提取 → 整合、持久化 + 检索、冲突时用户指令优先 |
| 认知 | s17 目标闭环 | 独立判断「何时真正完成」 | 独立评估器、目标不可能或超限时交还给人 |
| 上下文 | s06 子 Agent | 隔离噪声子任务 | 独立消息列表、只回传最终文本、超时回收 |
| 上下文 | s08 上下文压缩 | 上下文满了腾地方 | 先裁工具结果再摘要历史、保留权威指令 |
| 协作 | s10 任务系统 | 大目标拆小任务并持久化 | 依赖图、原子状态变更、并发锁 |
| 协作 | s11 后台任务 | 慢操作不阻塞 | 线程池、完成通知、超时清理 |
| 协作 | s12 定时调度 | 到点自动触发 | 持久化调度、幂等 |
| 协作 | s13 Agent 团队 | 多个 Agent 分工并行 | 原子认领任务、独立工作区、关停流程 |
| 编排 | s15 集成 Harness | 多个机制归一到一个循环 | 动态重建系统提示词、共享客户端 |
| 编排 | s16 工作流运行时 | 编排固定时写进代码 | 脚本拥有编排、生命周期事件、断点续跑日志 |

## 七层架构

| 层 | 名称 | 回答的问题 | 落地锚点 |
|---|---|---|---|
| ① | 交互层 | 谁在用、怎么用？ | 网页、App、小程序、API；同步或异步 |
| ② | 产品层 | 产品外壳是什么？ | 会话管理、请求路由、账户、业务逻辑 |
| ③ | 编排层 | AI 部分怎么运转？ | 主循环或流水线，以及选中的组件 |
| ④ | 模型层 | 智能从哪来？ | 主模型、辅助模型、路由、兜底、成本 |
| ⑤ | 能力集成层 | 怎么触达外部世界？ | 内部工具、检索、知识库、第三方 API |
| ⑥ | 数据层 | 什么要持久化？ | 业务数据、会话、记忆、日志、轨迹 |
| ⑦ | 基础设施层 | 怎么部署运行？ | 单进程或服务、队列、调度、监控 |

安全边界和可观测性贯穿各层，不单独成层。

## 六条落地标准

| 标准 | 什么算达到 |
|---|---|
| 可运行 | 一条命令能起，配置和密钥放在代码外 |
| 可容错 | 工具失败、模型幻觉、超时、越权都有明确降级路径 |
| 可观测 | 有日志、有指标、有轨迹数据 |
| 可测试 | 核心流程和工具分派有自动测试，权限和安全有边界测试 |
| 可部署 | 部署形态和启动文档明确 |
| 可度量 | PRD 的成功指标都能采集到 |
