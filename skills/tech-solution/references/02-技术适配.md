# 第 02 站：技术适配

**产物：** `技术适配声明.md`（模板 [../templates/技术适配声明.md](../templates/技术适配声明.md)）
**回答的问题：** 这是个什么形态的产品？按什么路径开发？用什么技术栈？哪些默认方案不用、为什么？

## 1. 产品形态

- **核心交互**：一次生成 / 多轮对话 / 分阶段确认 / 动态调用工具。
- **开发路径**（二选一，写原因）：
  - **A 后端先行**（默认）：后端能力 → 接口和自动化验证 → AI 效果验证 → 正式前端。适合表单提交、后台生成、下载结果类。
  - **B 纵向切片**：一个最小用户任务的最小界面 + 最小后端 + 真实模型，端到端跑通再扩展。适合人工确认、可视化编辑、多轮交互本身就是核心能力的产品。
- **验收界面**：无 / 临时验收界面（只服务验收，正式前端开始时废弃）/ 纵向切片界面（保留到正式产品）。判断只看一条：**会不会保留到正式产品**。
- **终端**：PRD 没指定时默认 Web。前端一次只做一个终端。

## 2. 默认技术基线

从零开始、没有既有系统约束的 AI 产品 MVP，直接用这组，不做开放式选型：

| 层 | 默认 | 一句话 |
|---|---|---|
| 后端语言 | Python 3.12 | 写业务、Agent 和 AI 能力 |
| 后端框架 | FastAPI | 把能力做成可测试、可调用的接口 |
| 数据校验 | Pydantic | 校验接口和模型的结构化输出 |
| 测试 | pytest | 自动检查业务逻辑和错误路径 |
| 模型调用 | 官方 SDK 或 OpenAI 兼容接口 | 国内主流模型大多兼容，换模型只改配置 |
| 代码管理 | Git | 保存变更；密钥检查依赖它 |
| Web 前端 | Next.js + TypeScript + Tailwind CSS | 正式前端阶段才引入 |
| 桌面 / 手机 / 小程序 | Tauri 或 Electron / React Native / 小程序原生 | 只在 PRD 指定时 |

按需模块，**只在 PRD 触发时引入**：

| 触发条件 | 模块 | 不该引入的情况 |
|---|---|---|
| 多实体关系、筛选统计、事务、用户账户、并发修改 | SQLite + SQLAlchemy（上线评估 PostgreSQL） | 单用户、本地、以文件为主时用带版本号的结构化文件 |
| 文档语义检索、知识库问答 | Chroma 持久化 | 没有 RAG，或小规模全文搜索就够 |
| 读写 Word / 解析 PDF | python-docx / pypdf | 没有这类文件 |
| 扫描件、图片文字 | OCR，在方案里选定 | 只有文本 PDF |
| 长任务、并发执行 | 持久化任务记录；多实例、同时 > 5 个长任务、单任务 > 10 分钟要跨重启续跑时才上任务队列 | 短请求 |
| 逐步展示模型内容 | SSE | 只看最终结果时用「提交 + 查状态」 |
| 大图片、音视频、生成文件 | 本地目录，上线评估对象存储 | 不往数据库塞大文件 |

已有项目：延续现有合理架构，只有违反底线、满足不了 PRD 或维护风险明显更高时才提局部迁移，不为对齐默认栈而重构。

## 3. 十条底线（每份声明都要逐条检查）

1. 密钥不进仓库、不进前端、不在对话 / 日志 / 截图里出现。
2. 重要业务数据、长任务状态、人工确认点要持久化，重启后可恢复。
3. 每个接口定义请求、响应、错误结构；错误统一 `{"error": {"code", "message"}}`；流式输出以 `done` 或 `error` 收尾。
4. 模型输出做结构校验；模型调用处理超时、失败、有限重试。
5. 高风险、不可逆、涉及费用或对外发送的动作，由确定性代码和人工确认约束，不交给模型自己决定。
6. 上传文件校验格式、真实类型、大小、文件名；日志不记密钥和完整用户文档。
7. 对外上线必须做到用户只能看自己的数据，权限在后端判断。
8. 收费的云资源，创建前告知费用并等产品经理确认。
9. 不删除已有功能、测试、用户数据。
10. 不用假数据冒充真实模型的验证结果；没有真实 Key 时如实写「待验」。

## 4. 产品经理确认三件事

声明写完，只请产品经理确认：

1. 你对目标用户、核心任务和交付范围的理解对不对；
2. 有没有新增 PRD 没要求的费用、外部平台、数据上传或上线范围；
3. 暂缓的能力会不会影响第一版验收。

三件事都没问题、「需要决定的问题」为「无」，就过关。
