# 第 01 站：PRD 体检

**产物：** `PRD补全清单.md`（模板 [../templates/PRD补全清单.md](../templates/PRD补全清单.md)）；PRD 小版本
**回答的问题：** 拿这份 PRD 开工，还缺什么？

PRD 写得不完整是常态。不得直接用默认值填满缺口往下跑，也不得一次抛出一大堆问题。

## 1. 对照八类信息逐项查

| # | 信息 | 在 PRD 哪里找 | 缺了会怎样 |
|---|---|---|---|
| 1 | 目标用户与核心任务 | 二、用户画像；三、功能清单 | 不知道为谁优化 |
| 2 | 输入、过程和产物 | 四、详细交互；全局上下文 | 数据结构和存储没法定 |
| 3 | Agent 主链路 | 四、系统处理流程；Agent 提示词设计 | 不知道是一次生成、分步确认还是自主调用工具 |
| 4 | AI 效果验收标准 | 三、验收标准；六、评测需求 | 没法判断做没做好 |
| 5 | 交付范围和优先级 | 三、功能清单与本期不做 | 范围失控 |
| 6 | 模型与成本约束 | 五、非功能「成本」；基础信息 | 选模型没有边界 |
| 7 | 数据与非功能要求 | 五、非功能（隐私、机密、用户量、时延、文件限制、部署位置） | 安全、架构决策没依据 |
| 8 | 上线与账号 | 五、安全性（登录、权限）；立项的范围 | 不知道是内部试用还是对外 |

再查三类 AI 特有的问题：

- **提示词能不能跑**：变量是否都在全局上下文里、工具是否都在工具表里、输出格式下游能不能解析。
- **兜底能不能做**：触发条件有没有阈值、系统行为有没有可执行的降级路径。
- **事实来源**：事实基座、知识库、检索资料从哪来，谁维护，多大量级。

## 2. 每个缺口分类

| 类 | 判断 | 例子 | 怎么处理 |
|---|---|---|---|
| **必须问** | 会改变目标用户、核心任务、成本、安全、隐私或交付范围 | 验收标准完全缺失；没说是否涉及企业机密；没说成本上限；主链路是一次生成还是分步确认没说清；内部试用还是对外 | 决策卡问产品经理，一轮不超过 5 个 |
| **可默认** | 其余 | 文件格式限制、响应时间、是否保留历史、接口前缀 | 用默认值填上，写理由，产品经理确认一次 |
| **矛盾** | PRD 两处说法冲突 | 功能清单说 3 秒返回，非功能说 10 秒 | 写推荐裁决，随必须问一起确认 |

AI 效果标准填不出来是最常见的缺口：不要逼产品经理写数字。记为「待样例打分」，交给 05 模型评测用真实样例打分后再定。

## 3. 决策卡

```markdown
### 问题 1：第一版是内部试用还是对外开放？
- 为什么重要：决定要不要做登录隔离、数据加密和备案，工作量差一倍
- 选项：A 只给内部 5 位研究员试用 / B 对外开放注册
- 推荐：A，立项批的是 POC，先验证效果
- 不选的后果：选 B 要先做账号体系和合规，MVP 推迟 2–3 周
（可以只回复「按推荐」）
```

## 4. 循环与落账

1. 产品经理回答后更新清单；还有必须问的，再来一轮，仍不超过 5 个。
2. 清单全部关闭后：按 prd skill 的「升版」规则把结论写回 PRD（升小版本，变更日志写「技术方案 PRD 体检：补 x 项」），可默认项写进 PRD 对应小节。
3. 所有决定写进 `决策台账.md`（模板 [../templates/决策台账.md](../templates/决策台账.md)），后面不再重复问。
4. `aipm.json`：必须问的每一项记 `decision`，回答后改 `resolved` 并写 `resolution`。
