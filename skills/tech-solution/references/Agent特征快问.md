# Agent 特征快问

技术方案第 03 站「架构设计」用。14 个特征决定选哪些 Agent 组件：特征表写进技术方案第 2 节，选型脚本直接读它，所以这里判清楚了，后面就不用再猜。

## 怎么问

1. **先自己判。** 拿 PRD 已经写下的内容（功能清单、流程设计、Agent 链路与提示词、兜底策略、本期不做）逐个判断，每条写依据，引用到章节。PRD 里能判出来的，不问用户。
2. **只问会改变选型、PRD 里又判不出来的。** 用提问工具（DeepSeek Harness 里是 ask_user_question）问，一次最多 3 个，最多两轮。每个问题用下表的大白话，带一个回答示例；选项固定四个，你根据 PRD 的线索判断的那个放第一个：
   - 需要（第一版就要）
   - 以后再做
   - 不需要
   - 说不清，帮我想想
3. **用户选「说不清，帮我想想」时**，给 2～3 个方向，每个一行：「A. 做法 —— 选它意味着什么」，破折号后面写代价（做起来更简单还是更费事、多花钱还是多花时间）。只用 PRD 里已有的信息，不假装知道 PRD 没写的事。最后一行写「回一个字母，或者说说你自己的想法」。还是答不上来就记「待确认」，同时写进决策台账的待定项。
4. **全部判完，整张表给用户看一眼**，随第 04 站的方案摘要一起确认。

## 判断口径

| 判断 | 什么时候用 |
|---|---|
| 需要 | 功能清单 P0 里明确要，或者核心闭环必然包含。碰到隐私、身份、支付数据时，「会不会做收不回的事」判需要 |
| 二期 | 有原文依据：功能清单里的 P1、P2，或者「后续」「以后」。没有原文依据不要判二期 |
| 不需要 | 核心闭环已经写清楚，这个特征不在里面。单人、单次、同步的产品，定时、多 AI 分工、插件生态这几项判不需要，不要判待确认 |
| 待确认 | 信息确实不够，而且问过用户也答不上来 |

## 14 个问题

| 特征 | 对应组件 | 大白话问题 | 回答示例 |
|---|---|---|---|
| `destructive_ops` | s03 权限系统 | AI 会不会替用户做「做了就收不回」的事？比如删东西、改别的系统里的数据、付钱、替人发消息；或者会碰到隐私数据（照片、证件、病历、精确位置）？ | 「会，要帮用户给客户发邮件」 |
| `audit_needed` | s04 钩子系统 | 有没有必须拦下来或者留记录的情况？比如敏感请求要拒答、每次操作要留痕给运营或法务查、每一步都要埋点统计？ | 「涉及未成年人的请求要直接拦下」 |
| `multi_step` | s05 任务规划 | 一次任务是不是要 AI 先列个计划，再一步步做，中途告诉用户做到哪了？（固定顺序调几个接口不算） | 「写调研报告：先列提纲，再一节一节写」 |
| `context_heavy` | s06 子 Agent | 会不会有一次要翻大量材料的活，或者可以同时查好几个方向，适合分给几个「小助手」分头干？ | 「同时查 5 家竞品的官网和定价」 |
| `large_knowledge` | s07 技能加载 | AI 要掌握的专业资料多不多？比如一大套规章制度、产品手册，用到哪部分再翻哪部分？（几百条字段整齐的数据、按条件筛就够的不算） | 「公司 300 页的报销制度」 |
| `long_sessions` | s08 上下文压缩 | 用户和 AI 会不会一聊就很久，或者中间要处理大量记录和日志，担心 AI 记不住前面说过的话？ | 「一次陪练 40 分钟」 |
| `cross_session_memory` | s09 记忆系统 | 要不要记住这个用户，下次来了不用重复说？比如口味、偏好、上次做的决定 | 「记住孩子的年龄和喜欢的玩具」 |
| `persistent_goals` | s10 任务系统 | 有没有要做好几天的大任务，关掉电脑下次还要接着做？ | 「一个课题分一周做完」 |
| `slow_operations` | s11 后台任务 | 有没有特别慢的步骤（要几分钟以上），希望用户不用干等，可以先去做别的？ | 「生成一段视频要 5 分钟」 |
| `scheduled` | s12 定时调度 | 要不要到点自动做事？比如每天早上推送、每周五出周报 | 「每周五晚上推一次周末精选」 |
| `parallel_isolated` | s13 Agent 团队 | 要不要好几个 AI 同时干不同的活，各管一摊、互不干扰，像一个小团队分工？ | 「一个写前端、一个写后端、一个测试」 |
| `external_ecosystem` | s14 MCP 插件 | 要不要接一整套现成的外部工具或插件，以后还会不断加新的？比如公司已有的系统、日历、网盘（只调一两个固定接口不算，那是普通工具） | 「接飞书文档、日历、多维表格，以后还要加」 |
| `fixed_orchestration` | s16 工作流运行时 | 整个流程是不是每次都按固定顺序走，比如「上传 → 翻译 → 校对 → 保存」，中间不需要 AI 自己判断走哪条路？ | 「是，永远是这四步」 |
| `auto_completion` | s17 目标闭环 | 要不要 AI 自己判断「做完了没有、够不够好」，不够就接着改，而不是做一次就交给用户？ | 「代码要跑通测试才算完」 |

s01（Agent 循环）和 s02（工具系统）恒选，s15（集成）按选中的数量自动定，都不用问。

## 写进技术方案的格式

写在技术方案第 2 节，列名不要改，第一列必须是带反引号的特征 id（`scripts/features_from_md.py` 按这个读）：

```markdown
### Agent 特征判断

| 特征 | 问的是什么 | 判断 | 依据 |
|---|---|---|---|
| `destructive_ops` | 收不回的操作、隐私数据 | 不需要 | 只读推荐，不采集精确位置（PRD 四、七） |
| `audit_needed` | 拦截、留痕、埋点 | 需要 | 拼酒、未成年人请求要拒答，运营每日抽检（PRD 七） |
| `cross_session_memory` | 记住用户 | 二期 | P2「个人偏好档案」（PRD 三） |
| `scheduled` | 到点自动做事 | 不需要 | 由用户提问触发 |
```

- 「判断」只写 需要 / 二期 / 不需要 / 待确认 四个词之一。
- 「依据」引用 PRD 章节；产品经理回答的写「产品经理：<原话>（日期）」。
- 14 行写全，不要只写「需要」的那几行：升版时要知道哪些是判过「不需要」的。
- 形态是单次调用、或产品不用模型时，整节写「不适用：<原因>」，不用填表。
