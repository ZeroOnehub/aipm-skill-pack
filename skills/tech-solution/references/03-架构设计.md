# 第 03 站：架构设计

**产物：** `技术方案.md`（模板 [../templates/技术方案.md](../templates/技术方案.md)）、`architecture-features.json`
**回答的问题：** 系统由哪几块组成、数据怎么存、接口长什么样、PRD 里的上下文、提示词和兜底在代码里落在哪、跑一次要多少钱、分几期做？

按模板的十二节顺序写。下面是每节的写法要点。

## 1. 要不要做成 Agent（第 1 节）

先判形态，三选一，**写 PRD 原文依据**：

| 形态 | 什么时候 | 例子 |
|---|---|---|
| 单次调用 | 一次输入一次输出，不需要工具 | 改写、翻译、分类 |
| 固定流水线 | 几个步骤顺序固定，每步可以调模型，但走哪步不由模型决定 | 上传 → 解析 → 生成大纲 → 逐章写 → 审计 → 优化 |
| Agent | 模型要根据情况自己决定下一步、调哪个工具、何时结束 | 自主调研、办事助手 |

能用流水线就不用 Agent：流水线更好测、更便宜、更稳定。PRD 链路表里环节顺序固定的，就是流水线，只是每个环节内部可能是一个小 Agent（会调检索工具）。

## 2. 特征判断与组件选型（第 2 节）

1. 按 [Agent特征快问.md](Agent特征快问.md) 判 14 个特征：先从 PRD 自己判，每条写依据；只把判不出来、又会改变选型的问产品经理（大白话，一次最多 3 个）。
2. 写进 `04-技术方案/architecture-features.json`（格式见 [组件与特征表.md](组件与特征表.md)），并在方案第 2 节放一张 14 行的特征表。
3. 跑选型脚本，结果原样贴进方案：

```bash
python3 <本 skill 目录>/scripts/select_components.py <项目根目录>/04-技术方案/architecture-features.json
```

同样的判断永远得到同样的选型，**不要手改脚本输出**。觉得结果不对，回去改特征判断和依据。

形态是单次调用的，这一节写「不适用：单次调用，不需要 Agent 组件」，跳过选型。

## 3. 七层架构（第 3 节）

一张 Mermaid 架构图 + 一张七层表（交互、产品、编排、模型、能力集成、数据、基础设施），每层写「用什么、为什么」。选中的组件放在编排层。安全边界和可观测性贯穿各层，在表下单独写两行。

## 4. 模型层（第 4 节）

只写**能力要求**和**候选方向**，具体模型由 05 评测定：

| 环节 | 能力要求 | 候选方向 | 备注 |
|---|---|---|---|
| 大纲 Agent | 中文长文结构、JSON 输出、工具调用 | 主力档 | |
| 审计 Agent | 细致比对、低误报 | 和正文用不同的模型，避免同一种盲点 | |

还要写：调用方式（OpenAI 兼容接口，模型名和地址放配置）、主备切换规则、超时和重试、token 上限。

## 5. 数据与状态（第 5 节）

- **业务实体表**：实体、关键字段、谁创建、生命周期。全局上下文（PRD 第四节）里的每个区块，写清存在哪（数据库表、JSON 文件、内存）。
- **状态机**：核心对象的状态和流转，和 PRD 的核心交互逻辑图一致；标出哪些状态要持久化（长任务、人工确认点必须持久化）。
- **存储选择**：默认文件还是数据库，按第 02 站的触发规则说明。

## 6. 接口与工具（第 6 节）

- **对前端的接口**：方法、路径、用途、请求要点、返回要点、错误码。流式接口写事件类型。
- **给 Agent 的工具**：PRD 工具汇总表里的每个工具，写实现方式（调哪个库、查哪张表）、超时、失败返回。
- 每个 P0 功能能找到对应接口；每个 PRD 工具能找到实现。

## 7. 上下文与提示词落地（第 7 节）

- 全局上下文：存储位置、读写时机、谁负责更新（如「每章写完由正文流程调用摘要工具更新 memory.chapter_summaries」）、并发和续跑。
- 提示词：**PRD 第四节的提示词原文就是第一版**，放进代码仓库的 `prompts/<环节>.md`，变量用模板渲染；改提示词要升版本号并重跑评测集。不在方案里另写一版提示词。
- 结构化输出：用 Pydantic 定义每个 Agent 的输出结构，解析失败按兜底处理。

## 8. 兜底实现（第 8 节）

PRD 第七节每一行，写对应的实现：在哪一层判断、阈值放哪个配置、降级调什么、前端收到什么错误码。再补四类 PRD 可能没写的：工具失败、模型幻觉（结构校验 + 事实比对）、超时、越权。

## 9. 可观测与埋点（第 9 节）

- 日志：每次模型调用记模型名、耗时、输入输出 token、成本、结果状态；不记用户文档原文和密钥。
- 轨迹：多环节链路记每一步的输入输出摘要，评测和排错要用。
- 埋点：PRD 埋点表的每个事件，写在哪里上报（前端 / 后端）。

## 10. 成本测算（第 10 节）

按环节估：单次调用的输入 token × 输入单价 + 输出 token × 输出单价，乘以每个任务的调用次数，得到**单次任务成本**；再乘以预计任务量得到月成本。和 PRD 非功能「成本」上限对比。

单价先用候选方向的公开价格估（标【测算】和价格页日期），05 评测定了模型再回填实际数。

## 11. 开发分期（第 11 节）

MVP 后端按「核心链路先通」分期，每期一个能验收的结果：

| 期 | 范围 | 验收方式 | 依赖 |
|---|---|---|---|
| 1-1 | 大纲生成 + 事实基座确认（真实模型） | 用评测集的大纲题跑通，产品经理看 5 份样例 | 模型 Key |
| 1-2 | 逐章正文 + 记忆 | …… | |

正式前端放在后端核心链路验收之后（纵向切片路径除外）。

## 12. 风险与待定（第 12 节）

技术风险（效果、性能、成本、合规、依赖）每条写：可能性、影响、应对、谁来盯。待定项引用决策台账编号。

## 关卡

- [ ] 形态判断有 PRD 原文依据
- [ ] 14 个特征都有判断和依据，选型结果是脚本原样输出
- [ ] PRD 每个 P0 功能有接口，每个工具有实现，每条兜底有实现
- [ ] 全局上下文每个区块写清存储位置和更新时机
- [ ] 提示词以 PRD 原文为第一版，写明存放和升版规则
- [ ] 成本测算和 PRD 上限比过
- [ ] 开发分期每期有可验收的结果
