# 复盘

> 改编自 [phuryn/pm-skills](https://github.com/phuryn/pm-skills) 的 `retro`（MIT，Paweł Huryn）。改动：中文化；新增「上线复盘」格式（目标对照 + 指标 + 过程），可以读 PRD 和指标复盘作为输入；产出物默认存进拾阶的复盘目录。

做一次能带出改进行动的结构化复盘。语气保持建设性：目的是改进，不是追责。

## 输入

用户给了迭代数据、速度图、团队反馈或上次复盘记录，先读完。在拾阶里，上线复盘先读：`02-PRD/PRD.md`（目标、上线条件、停止条件）、`06-上线复盘/` 里的指标复盘、以及上一次复盘记录（如果有）。

## 流程

### 1. 选格式

按场景选，或让用户挑：

**A：开始 / 停止 / 继续**
- 开始：我们应该开始做什么？
- 停止：我们应该停止做什么？
- 继续：哪些做得好、要保持？

**B：4L（喜欢 / 学到 / 缺少 / 渴望）**
- 喜欢：团队享受什么？
- 学到：获得了什么新认识？
- 缺少：缺了什么？
- 渴望：希望有什么？

**C：帆船图**
- 风（推动我们）：什么在推着我们往前？
- 锚（拖住我们）：什么在拖慢我们？
- 礁石（风险）：前面有什么危险？
- 岛（目标）：我们要去哪？

**D：上线复盘（目标对照）**，功能或产品上线后用：
- 当初的目标和上线条件是什么？（从 PRD 摘）
- 实际结果是什么？（从指标复盘摘，带数字和对比）
- 差距在哪，为什么？（区分：判断错了 / 执行出了问题 / 外部变化）
- AI 部分的表现：能力边界划得对不对？哪些兜底被真的触发了？评测通过率和线上感受一致吗？
- 要不要触发停止条件？继续、调整还是停？

### 2. 整理原始反馈

用户给了零散反馈（便签、问卷、聊天记录）时：相似的归成主题；找出被提到最多的话题；留意情绪模式（沮丧、兴奋、困惑）。

### 3. 分析表现

- 目标：达成、部分达成还是没达成？
- 承诺量 vs 完成量（承诺多了？少了？）
- 遇到了哪些卡点，怎么解决的
- 协作模式（什么有效、什么无效）

### 4. 产出行动项

| 优先级 | 行动 | 负责人 | 截止 | 怎么算做到 |
|---|---|---|---|---|
| 1 | [具体、可执行的改进] | [人或角色] | [日期] | [衡量方式] |

- 最多 2～3 条，多了做不完。
- 每条都要具体、能分配、能衡量。
- 有上次复盘的记录，就检查那些行动做完没有。

### 5. 写复盘纪要

```
## [迭代 / 版本] 复盘 —— [日期]

### 表现
- 目标：[达成 / 部分达成 / 未达成]
- 承诺：[X] | 完成：[Y]
- （上线复盘）关键指标：[指标：目标 → 实际]

### 主要主题
1. [主题] —— [概述]

### 行动项
1. [行动] —— [负责人] —— [截止日期]

### 上次复盘行动的落实
- [上次的行动] —— [状态：完成 / 进行中 / 未开始]

### 结论（上线复盘）
[继续 / 调整 / 停止，以及理由]
```

## 产出位置

保存为 Markdown。在拾阶里存到当前项目的 `06-上线复盘/复盘-<版本或日期>.md`。
