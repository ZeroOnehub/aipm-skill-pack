# AI 项目多问四句

普通项目过三问就够了；AI 项目还要多问四句。每一问都要写成报告里能被检查的内容，不接受「后续优化」「持续迭代」这类回答。

## 01 该不该用 AI

- AI 适配三条件逐条判断：重复性高、标准化程度高、人力瓶颈明显。**三条都占才用。**
- 改流程能不能更便宜？写出你考虑过的非 AI 方案，以及为什么不够。按 **AI 程度阶梯**从低往高比，选能解决问题的最低一级：

  | 级 | 方案 |
  |---|---|
  | 0 | 不做（问题其实能忍） |
  | 1 | 改流程、加模板、写操作手册、做培训 |
  | 2 | 采购现成的 SaaS 或工具 |
  | 3 | 简单软件或规则自动化 |
  | 4 | AI 辅助（AI 出草稿，人拍板） |
  | 5 | AI 自主执行（Agent 自己做完，人抽查） |

  跳过低级直接选 4、5 级的，要写清低级方案为什么不够。
- 模型变强以后，我们更值钱还是被吞掉？写出我们的壁垒在哪（独有数据、场景入口、流程嵌入、合规资质、行业知识）。
- 标准化要看实际：同一样本不同人打分是否一致？标准写的和用的是否一致？不一致的，第一个闸门就是「先统一人工标准」。

## 02 做到多好才算行

必须**量化**：

| 要写的 | 示例写法（替换成你的项目） |
|---|---|
| 核心能力指标 | 识别准确率 ≥ X%；证据正确率 ≥ X% |
| 跟人比 | 人—AI 评分一致性 ≥ X；不低于人工基线 |
| 体验指标 | 响应时间 P90 ≤ X 秒 |
| 安全指标 | 红线内容召回率 ≥ X%；安全事件 0 起 |
| 评测集 | 来源（真实样本 / 构造样本）、规模、谁标注、标注一致性怎么保证 |
| 门槛从哪来 | 对齐人工水平 / 对齐竞品实测 / 业务可接受的最低值，写清依据 |

门槛定不出来时，写「第一阶段先建评测集和人工基线，某时间点后定门槛」，并把它设为第一个闸门。

## 03 出了错，谁兜

画清**人机分工**：AI 管哪一段，规则管哪一段，人管哪一段。用一张现状 → 目标的节点表写出来：

| 流程节点 | 现在谁做（AS-IS） | 以后谁做（TO-BE）：规则 / 人 / AI | AI 的输入和输出 | AI 的自主程度 | 出错时谁接手 |
|---|---|---|---|---|---|
| | | | | 只出草稿 / 人确认后执行 / 自动执行 | |

只有标成 AI 的节点才进入第 02 问的质量门槛和第 04 问的成本测算；其他节点不要因为「顺便」被 AI 化。

- AI 没把握时怎么办：低置信度、证据不足、规则冲突时，不输出确定结论，转人工或让用户确认。
- 高风险判断（考核、资金、医疗、法律、人身、隐私）：AI 只能辅助，不能拥有最终决定权；写清哪些结果**不得**未经人工复核就生效。
- 用户能不能纠错、申诉；错了以后怎么回收、怎么改进。
- 安全事件的处理人和处理方式：谁负责、多快响应、什么情况下停掉试点。

## 04 数据和成本

| 要写的 | 内容 |
|---|---|
| 数据从哪来 | 训练 / 评测 / 运行时各用什么数据，谁负责提供 |
| 权限和合规 | 是否涉及个人信息、录音录像、敏感数据；需要谁审批；审批没过怎么办 |
| 单次成本 | 用一次花多少（模型调用、语音、存储），按什么假设估算 |
| 规模成本 | 按预期用量算月成本；用量翻倍时怎么办 |
| 成本谁出 | 预算来源；按阶段审批 |

成本拿不到准确报价时，写估算口径并标【测算】，把「拿到报价后冻结预算」放进决策待办。

**两层账分开算**：

- **这一阶段的投入值不值**：花这笔钱、这些人周，换来的信息能不能改变下一步的决定？POC 阶段只算这一层。
- **规模化以后划不划算**：全量后的收益和总成本（一次性投入 + 持续的模型调用、数据维护、评测、监控、人工兜底），标【测算】，写清假设和回本时间。

**省下的时间要说清去哪了**：「每人每天省 2 小时」不是收益，除非写清这 2 小时被重新分配到了什么更有价值的工作上，或者减少了多少外包、加班、招聘。

## 写进报告的格式

报告第 07 节用四个小标题，各自一段结论 + 一张表。答不上来的地方写「待验证：怎么验证、何时验证、谁负责」，不留空、不含糊。
