# 第 02 站 · 找到真用户

**要回答：** 谁真有这个问题，有多疼？
**交付：** `02-用户画像与调研结论.md`（模板：[templates/02-用户画像与调研结论.md](../templates/02-用户画像与调研结论.md)）

先画，再验。画像是假设，调研是验证。

## 1. 分群

三种常用分法，选一到两种：

| 分法 | 怎么分 | 适合 |
|---|---|---|
| 生命周期 | 新 / 活跃 / 沉睡 / 流失（沉睡、流失要带时间窗口，如 90 天） | 1→N，看人在哪一步走 |
| 消费能力 | 频次 × 金额四象限 | 有付费的产品 |
| 购买动机 | 要最好的 / 图便宜 / 为了解决问题 / 发烧友 | 0→1，找最痛的那群 |

1→N 还常按**来源**分：主动来的和顺带来的（比如因为别的产品捆绑才接触到）是两拨人，引导方式完全不同。

## 2. 写画像

没用的画像只有人口统计（年龄、城市、学历）。有用的画像写四样：

1. **他知道什么**：对这个领域、对 AI 的认知水平。
2. **他在乎什么**：判断好坏的标准，愿意为什么付出。
3. **他在什么时候用**：触发时刻。
4. **他因为什么卡住**：具体卡点。

每个画像配：一句原话、一件做过的事。B 端产品要分清角色：实际使用的人、提供供给的人、审核兜底的人、关心结果的人，四种关系各写一张。

## 3. 去验证：用研五步

1. **定目标**：这次要弄清哪件事？对应第 01 站里标了「待验证」的项。
2. **选用户**：四类各问不同的事。

   | 类型 | 问什么 | 去哪找 |
   |---|---|---|
   | 重度用户 | 深度痛点、用到了哪个边界 | 产品内问卷、粉丝群 |
   | 边缘用户 | 没想到的场景 | 社区话题帖 |
   | 流失用户 | 为什么走、走去了哪 | 回访、竞品评论区 |
   | 潜在用户 | 为什么还没来、卡在哪 | 竞品评论区、销售拜访 |

3. **设计问题**：按 The Mom Test，问他的生活和做过的事，别问看法，别带着答案去问。

   | 坏问题（问看法） | 好问题（问做过的事） |
   |---|---|
   | 你觉得 AI 能帮你提高效率吗？ | 你上周最耗时间的一件工作是什么？当时怎么做的？ |
   | 你喜欢这个功能吗？ | 你上次用它是什么时候？发生了什么？ |
   | 这个想法好不好？ | 这件事你现在怎么处理？花了多少钱 / 时间？ |

4. **执行**：定量看多少人这样（问卷、数据），定性看为什么这样（访谈、观察）。两者都要：定量让老板信规模，定性让方案有依据。
5. **整理输出**：每条结论配原话或数字。访谈记录时区分：原话、数字、语气（坚定还是客气）。客气话不算证据。

## 你能帮用户做什么

- 根据第 01 站的待验证项，**生成访谈提纲**（10 个以内的好问题）和问卷题目。
- 用户贴回访谈记录、问卷结果、用户反馈后，帮他拆：真需求、原话、做过的事、真话和客气话。
- **用户没有真实证据时**：说明风险，问用户选哪种方式：
  1. 先去访谈（推荐，给出提纲，等用户回来再继续）。
  2. 让你做【模拟】访谈，只用来打磨假设和提纲，每处打【模拟】标签，结论写成「待验证假设」，并在档案的数据缺口里登记。
  3. 用公开的用户反馈（应用商店评论、社区帖子）先顶上，标【公开资料】并附链接。

## 调研总结写四项

| 项 | 写什么 |
|---|---|
| 核心用户 | 当前证据下问题最集中的那群人；第二优先待验证的人群 |
| 核心场景 | 一个具体场景 |
| 核心问题 | 一句话，没有功能名 |
| 真实需求 | 用户需要在什么条件下完成什么，得到什么 |

每项后面写证据强度：充分 / 有信号待验证 / 缺证据。

## 自检清单（关卡）

- [ ] 画像写了四样（知道 / 在乎 / 何时用 / 卡在哪），不是人口统计
- [ ] 每个画像有一句原话和一件做过的事
- [ ] 访谈问题里没有问看法的问题
- [ ] 至少 2 个真实用户的原话支撑核心问题；不足时，已按用户选择标【模拟】或【公开资料】，并登记数据缺口
- [ ] 说的和做的冲突时，写了信哪个、为什么
- [ ] 每个数字写了分母和口径；相关性数据没被写成因果
- [ ] 第 01 站的问题定义被验证、修正或推翻（推翻就回第 01 站重写）
