# 两类立项：0→1 和 1→N

两类共用六站方法，差别在于证据从哪来、报告重心在哪。开场确认类型后，按下表调整每站的做法。

## 一眼区分

| | 0→1 新项目立项 | 1→N 阶段规划 |
|---|---|---|
| 决策问题 | 做不做？做的话第一版多小？ | 下一阶段做什么、先做什么、要多少资源？ |
| 最硬的证据 | 真实用户访谈、替代方案的行为证据、POC 结果 | 漏斗与行为数据、用户反馈（VOC）、竞品实测 |
| 最大的风险 | 问题是假的；AI 做不到门槛 | 资源被摊薄；做了很多但核心指标不动 |
| 结论形态 | 做 / 不做 / 有条件做（常见：小范围试点 + 分阶段批钱） | 若干专题 + 版本节奏 + 资源缺口 + 砍需求顺序 |
| 竞品分析目的 | 0→1：市场有没有空白，要不要做 | 1→N：先迭代哪个；对手出招要不要跟；定价 |

## 每站的调整

### 01 把问题说清

- **0→1**：从用户的一个具体场景出发，问三次为什么，写问题定义卡。
- **1→N**：先写**一句话业务公式**，把要提升的核心指标拆成几个可干预的因子（如「收入 ＝ 用户愿不愿意用 × 用完觉不觉得值」）。再用**漏斗或旅程数据**找出流失最大的几段，每一段写一张问题定义卡。问题通常有 2 到 4 个，后面会对应成专题。

### 02 找到真用户

- **0→1**：重点在验证问题是否真实存在、有多疼，访谈至少 2 个真实用户，拿到原话和做过的事。
- **1→N**：重点在**分群**，看不同用户群为什么走、为什么留。常见分法：按来源（主动来的 / 顺带来的）、按生命周期、按付费意愿。每一群写「今天为什么走」和「我们希望变成」。

### 03 收进需求池

- **0→1**：需求池通常不大，重点是把调研结论拆成动作。
- **1→N**：需求池往往已经存在且很长。先**按问题归入专题**，再给每条需求标：承接团队、对瓶颈团队的负载（重 / 中 / 轻）、状态。纳入不了本期的需求单独列表，**每条写不纳入的理由**；已明确放弃的方向也写下来。

### 04 看清对手

- **0→1**：四类竞品都要找，尤其替代品（用户现在怎么凑合）。
- **1→N**：重点做**竞品实测**：同一批任务，自己和对手各跑一遍，按几个维度打分，写清样本量。再看对手把钱收在哪、能力差距在哪，结论落到「学它的做法，不比它的规模」：只补最重要、最紧急、最适合自己的部分。

### 05 排出先后

- **0→1**：Kano 分类 → 价值 × 成本四象限 → MVP（只验证一个假设）。
- **1→N**：先写**取舍原则**（3 到 5 条，每条都能直接拿来判断一条需求做不做）。再按**资源瓶颈**排：找出最紧张的团队，把「不占瓶颈团队」的需求提前，让有余力的团队先动起来。最后写**资源不足时的砍需求顺序**（L0 绝不砍 / L1 优先保 / L2 可后移 / L3 先砍），每层写理由。

### 06 拍板立项

- **0→1**：三问 + 决策矩阵 + AI 四问，常见结论是「有条件立项」：小范围、影子模式或试点，钱分阶段批，每个阶段设闸门。
- **1→N**：结论是一张**版本节奏表**：用一个外部锚点（大促、新品上市、财年节点）倒推版本窗口，把专题排进版本，标出最紧的一版和原因；再列**决策待办**（事项、时间、责任人）和**资源缺口**。原则是「先列需求，再谈资源，最后取舍」，顺序不能反。

## 报告的侧重

两类都用同一份报告模板（[templates/立项报告.md](../templates/立项报告.md)），模板里标了每节在两类中的写法。1→N 的报告会更长，第 05、06 节是重心；0→1 的报告第 01、02、07 节是重心。
