# 立项报告写作规范

读者是**拍板的老板或管理层**。他们时间少、要结论、会追问证据和代价。报告要做到：只看第一页就能拍板；想追问时每个结论都能翻到证据。

## 结构

按 [templates/立项报告.md](../templates/立项报告.md) 写。骨架和每节的来源：

| 节 | 内容 | 来自哪一站 |
|---|---|---|
| 00 一页纸结论 | 决策问题、结论、一句话逻辑、问题→行动、投入、停止条件、需要拍板的事 | 全部 |
| 01 背景与问题 | 为什么现在做、问题定义、业务公式 / 漏斗诊断 | 01 |
| 02 用户与场景 | 谁、多疼、证据 | 02 |
| 03 市场与竞品 | 四类竞品、对比、差异化公式、反方论证 | 04 |
| 04 目标与成功指标 | 用户旅程「今天 / 目标 / 怎么衡量」、过程指标→结果指标 | 02、05 |
| 05 方案与第一版范围 | 取舍原则、要验证的假设、必须做 / 明确不做 / 以后 | 03、05 |
| 06 投入与计划 | 团队、分阶段与闸门、版本节奏、资源缺口 | 05、06 |
| 07 AI 方案四问 | 该不该用、做到多好、谁兜、数据和成本 | 01、06 |
| 08 风险与停止条件 | 风险表、降级方案、停止条件 | 06 |
| 09 决策待办与数据缺口 | 待办表、缺口清单 | 全部 |
| 附录 | 需求池、未纳入需求、竞品详表、调研记录、证据台账、参考来源 | 全部 |

## 写法

### 结论先行

- 每一节开头第一段就是这一节的结论，后面才是展开和证据。
- 第 00 节「一页纸结论」写在最后、放在最前：其他节写完再回头写它。
- 一页纸结论里的每一句，都要能在正文里找到对应的展开。

### 大白话

- 短句。一句话只说一件事。
- 用户视角的说法：写「用户拿到设备不知道能录音」，不写「功能认知度不足」。
- 不用黑话：赋能、抓手、闭环打通、链路、颗粒度、心智占领、全域、降本增效、组合拳、底层逻辑……能换成具体动作和数字的都换掉。
- 不用空形容词：「极大提升」「显著优化」「全面升级」，换成「从 X 到 Y」。
- 对比要具体：「我们 172 秒，对手 118 秒」比「我们阅读效率较低」有力。

### 让老板一眼看懂的写法

- **一句话逻辑**：用一个等式或一条因果链把整份报告串起来（如「收入 ＝ 愿不愿意用 × 用完值不值」）。
- **问题 → 行动对应**：每个问题对应一个专题或动作，一一对上，不多不少。
- **今天 vs 目标**：用户旅程表，每一步写「今天的样子 / 要做到的样子 / 怎么衡量」。
- **指标分两种颜色**：有基线的（写「现状 → 目标」，目标写依据，如对齐竞品实测）和待建基线的（写「无埋点 → 建立基线」，不编数字）。
- **过程指标落到结果指标**：每个过程指标说清它推动哪个结果指标。
- **不做的事和做的事一样重要**：明确不做、未纳入需求、放弃的方向，都写理由。
- **决策待办有人有时间**：不写「后续对齐」，写「X 月 X 日前，某某和某某对齐某事」。

### 证据

- 正文里的数字和引语带证据标签（见 SKILL.md）。HTML 里用小标签样式显示。
- 【测算】【模拟】【业务方表达】不能出现在结论句的主语位置，只能出现在「依据」或「待验证」里。
- 每节末尾可以写一行「数据来源」，列出本节用到的来源。

### 篇幅

- 一页纸结论：一屏能看完（约 400 到 600 字 + 一张小表）。
- 正文每节：0→1 项目 300 到 800 字；1→N 项目第 05、06 节可以更长，用表格承载细节。
- 细节放附录，正文只放支撑判断的部分。

## HTML 版

- 复制 [templates/立项报告.html](../templates/立项报告.html)，保留 `<style>` 和组件结构，替换内容。不要引入外部脚本和外部字体，保证离线能打开。
- 需要新增样式时，写进模板原有的 `<style>` 里面，放在 `</style>` 之前。`</style>` 和 `</head>` 之间不能有任何文字，否则 CSS 会直接显示在页面顶部。
- 模板里有这些组件，按需使用，不需要的删掉：一页纸结论卡、指标卡、漏斗、旅程对比表、问题→行动卡、竞品对比表、决策矩阵、范围三栏、闸门时间线、砍需求分层表、风险表、待办表、证据标签、折叠附录。
- HTML 与 Markdown 内容一致。改了一份，同步改另一份。
- 生成后用浏览器打开检查一次（有浏览器工具就截图看；没有就请用户打开看），确认没有残留的模板占位符（搜 `{{`），页面顶部也没有露出 CSS 代码。

## 成稿自检清单

- [ ] 只看第 00 节就能知道：做不做、投多少、多久、什么情况停、要老板拍什么
- [ ] 第 00 节写明批到哪一步、批准范围；正文没有超出这一步的承诺
- [ ] 每节第一段是结论
- [ ] 每个问题都对应到一个行动，每个行动都对应到一个问题
- [ ] 所有数字有来源标签，有分母和口径
- [ ] 【测算】【模拟】【业务方表达】【文档声称】没有被写成事实；【冲突】的数字两边都列出来了
- [ ] 每个问题至少和一个非 AI 方案比较过
- [ ] 有明确不做清单，每条有理由
- [ ] 有量化的 AI 门槛和评测集说明
- [ ] 有人机分工，写清 AI 不能决定什么
- [ ] 有分阶段闸门，每个闸门有不过闸怎么办
- [ ] 有可观测的停止条件
- [ ] 有事前验尸：老虎有应对和负责人，大象已转成待验证假设
- [ ] 一票否决项逐项写明是否通过，没有被总分抵消
- [ ] 有决策记录与预测，写了复盘日期
- [ ] 决策待办每条有时间和责任人（或标「待定」并点出）
- [ ] 数据缺口单独列出
- [ ] 全文没有黑话和空形容词
- [ ] HTML 无残留占位符，与 md 内容一致
