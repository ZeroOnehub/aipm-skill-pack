# 假设地图与验证实验

**用在：** 第 05 站定核心假设之前；第 06 站设计闸门时。
**为什么：** 好团队默认自己至少四分之三的想法不会像预期那样奏效。立项要回答的不是「这个想法好不好」，而是「最可能让它失败的那个假设，我们有没有用最便宜的办法验过」。

> 方法来源：Teresa Torres《Continuous Discovery Habits》的四类产品风险；Paweł Huryn 扩展的八类风险和「影响 × 风险」排序（[phuryn/pm-skills](https://github.com/phuryn/pm-skills)，MIT）；Alberto Savoia《The Right It》的预型实验；[caalvinz/opportunity-discovery-skill](https://github.com/caalvinz/opportunity-discovery-skill)（MIT）的「判别性实验」和预先承诺的判定标准。本文为改写，不是翻译。

## 1. 列假设：八类风险 + AI 三类

从三个视角各想一遍「为什么会失败」：产品（需求、付费意愿、竞争）、设计（第一次用、上手、持续用）、研发（自建还是采购、规模、技术债）。然后按类登记：

| 类别 | 要问的 |
|---|---|
| 价值 | 用户真的要吗？会一直用吗？ |
| 可用性 | 用户会用吗？上手够快吗？会不会增加负担？ |
| 商业可行 | 能收到钱或换到公司要的东西吗？值这个成本吗？合规吗？ |
| 技术可行 | 现有技术做得到吗？能集成吗？能规模化吗？ |
| 伦理 | 该不该做？会不会伤害用户？ |
| 上市 | 有渠道吗？用户愿意试吗？时机对吗？ |
| 战略 | 别人能不能轻易抄？这是我们最该解决的问题吗？ |
| 团队 | 人对吗？工具够吗？关键人会不会走？ |
| **AI · 数据** | 训练、评测、运行时的数据拿得到吗？权限批得下来吗？ |
| **AI · 质量门槛** | 模型能达到业务可接受的门槛吗？人工标准本身统一吗？ |
| **AI · 单位成本** | 用量上来后，每次调用的成本还撑得住吗？ |

每条假设写成可证伪的句子：「[谁] 在 [什么情况] 下会 [做什么]，达到 [什么程度]」。写不成这种句子的，多半还是一句愿望。

## 2. 排序：重要性 × 证据强度

| | 证据强（已验证） | 证据弱（没验证） |
|---|---|---|
| **假设错了会让项目失败** | 放心往前走 | **最危险假设：先验它** |
| **假设错了影响不大** | 不用管 | 记下，以后再说 |

- 「证据强弱」用证据标签判断：只有【用户原话】【行为数据】【实测】【公开资料】撑着的算强；只有【业务方表达】【文档声称】【测算】【模拟】【AI 推断】的都算弱。
- 最危险假设通常只有 1～3 条。第 05 站的「核心假设」就从这里选。

## 3. 设计最便宜的判别性实验

判别性实验的意思是：**结果能改变决定**。做完无论成败都不改变决定的实验，不值得做。

优先观察真实行为，不要先做精致原型：

| 实验 | 怎么做 | 适合验证 |
|---|---|---|
| 看现有凑合办法 | 观察或调取用户现在怎么凑合、花多少时间钱 | 价值、痛的程度 |
| 假门测试 / 落地页 | 放一个入口或页面，看多少人点、留联系方式 | 兴趣、上市 |
| 预售 / 等候名单 | 让人付定金、排队、给出时间 | 付费意愿（真金白银才算数） |
| 礼宾式 MVP | 人工一对一把服务做出来交付 | 价值、流程是否走得通 |
| **绿野仙踪测试** | 前台看起来是 AI，后台由人完成 | AI 产品专用：用户要不要这个结果，先于「AI 能不能做到」 |
| 对比试用 | 同一批真实任务，人工 / 现有工具 / 新方案各跑一遍 | 价值、可用性 |
| 离线 POC | 拿真实数据离线跑模型，对照人工结果 | AI 质量门槛 |
| 试点承诺 | 让业务方签一个小范围试点并指定负责人 | 商业可行、组织意愿 |

原则：
- 测「愿意付出什么」，不测「感不感兴趣」。时间、钱、声誉的投入才是可靠信号。
- 用自己收集的数据，少拿别人的市场报告类比。
- 能离线、异步验证的，不先做实时。

## 4. 实验卡（每个闸门一张）

做之前填好，做完才填结果。**判定标准必须在看到结果之前写死。**

```
实验名：
要支撑的决定：做完要决定什么
最危险假设：
可证伪的说法：____ 在 ____ 下会 ____，达到 ____
对立解释：如果结果好看，还可能是因为什么？
方法、样本、对照：
隐私、安全、知情同意：
成功标准：            失败标准：            说不清时：
时间上限：            成本上限：            负责人：
成功 → 下一步：
失败 → 下一步：（停止 / 降级 / 转向）
说不清 → 下一步：
结果（真正做完后才填）：
```

没有现成数值门槛时，不要编一个当成事实。写「先建基线，X 时间后定门槛」，并把建基线作为第一个实验。

- [ ] 最危险假设 ≤ 3 条，并说明为什么是它们
