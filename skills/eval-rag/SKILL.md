# 评测 RAG

> 改编自 [hamelsmu/evals-skills](https://github.com/hamelsmu/evals-skills) 的 `evaluate-rag`（MIT，Hamel Husain）。改动：中文化；名字改为 `eval-rag`；产出物默认存进拾阶的评测目录。公式和流程保持原样。

## 总览

1. 先对端到端轨迹做错误分析，判断失败来自检索、生成还是两者都有。
2. 建检索评测集：问题配上相关的文档分块。
3. 用 Recall@k 衡量检索质量（第一轮召回最重要）。
4. 单独评生成：忠实度（有没有基于资料）和相关性（有没有回答问题）。
5. 检索是瓶颈时，先网格搜索分块策略，再调生成。

## 前提

选指标之前先对 RAG 轨迹做完错误分析（见 `eval-error-analysis`）。看清检索到了什么、模型实际需要什么，判断问题在检索、生成还是两者。先修检索。

## 流程

### 检索和生成分开评

各自独立衡量，每个检索阶段用合适的指标：
- **第一轮召回**：优化 Recall@k。宁可带进噪声，也要把相关文档都召回。
- **重排**：优化 Precision@k、MRR 或 NDCG@k，把最相关的排到前面。

### 建检索评测集

需要「问题 + 标准答案所在的分块」。

**人工整理（质量最高）**：写真实的问题，把每个问题对应到包含答案的具体分块。

**合成问答（可扩展）**：对每个分块，让大模型抽一个事实，再出一个只靠这个事实就能回答的问题。

合成问答提示词：

```
给定一段文本，从中抽取一个具体、独立的事实。
然后写一个问题，这个问题能被这个事实直接、无歧义地回答。

按 JSON 输出：
{ "fact": "...", "question": "..." }

文本："{text_chunk}"
```

**对抗问题**：造一些更难的问题，和多个分块的内容都像，但只有一个分块能回答。

做法：
1. 选一个含明确事实的目标分块 A。
2. 用 embedding 搜索找相似分块 B、C（术语相同但没有答案）。
3. 让大模型用 B、C 的术语写一个只有 A 能回答的问题。

例：
- 分块 A：「2020 年 4 月，公司季度营收下降 17%，是 2008 年以来最大降幅。」
- 分块 B：「2008 年金融危机期间公司出现大幅亏损。」
- 生成的问题：「公司什么时候出现了 2008 年金融危机以来最大的营收下滑？」

只有 A 有答案，B 是看起来合理的干扰项。

**过滤合成问题**：用带示例的大模型打分评「真实度」，只保留 4～5 分（1～5 分制）的。这里用分级量表没问题，因为目的是给数据集做粗排序，不是测失败率。

### 检索指标

**Recall@k**：前 k 个结果里找到了多少相关文档。

```
Recall@k = (前 k 个里的相关文档数) / (该问题的相关文档总数)
```

第一轮召回优先看召回率。大模型能忽略无关内容，但没法从缺失的内容里生成答案。

**Precision@k**：前 k 个结果里有多少是相关的。

```
Precision@k = (前 k 个里的相关文档数) / k
```

用于评重排。

**MRR（平均倒数排名）**：第一个相关文档出现得多早。

```
MRR = (1/N) * sum(1/第一个相关文档的排名)
```

最适合只需要一个关键分块的单事实查询。

**NDCG@k（归一化折损累计增益）**：文档相关程度有高低时用，越相关的排越前得分越高。

```
DCG@k  = sum over i=1..k of: rel_i / log2(i+1)
IDCG@k = 按相关度降序排列时的 DCG@k
NDCG@k = DCG@k / IDCG@k
```

注意：把一堆弱相关文档排得很完美，得分可能高过把一个强相关文档排得靠后。要配合 Recall@k 一起看。

**k 怎么选**：看问题类型。事实查询 k=1～2；综合类问题（「总结一下市场趋势」）k=5～10。

#### 指标怎么选

| 问题类型 | 主指标 |
|---|---|
| 单事实查询 | MRR |
| 需要覆盖面 | Recall@k |
| 排序质量重要 | NDCG@k 或 Precision@k |
| 多跳推理 | 两跳 Recall@k |

### 评测和优化分块

把分块当成可调的超参数。同一个检索器，光换分块，指标就会变。

**固定长度分块做网格搜索**：试不同的分块大小和重叠，每种配置重新建索引，在评测集上测检索指标。

示例：

| 分块大小 | 重叠 | Recall@5 | NDCG@5 |
|---|---|---|---|
| 128 tokens | 0 | 0.82 | 0.69 |
| 128 tokens | 64 | 0.88 | 0.75 |
| 256 tokens | 0 | 0.86 | 0.74 |
| 256 tokens | 128 | 0.89 | 0.77 |
| 512 tokens | 0 | 0.80 | 0.72 |
| 512 tokens | 256 | 0.83 | 0.74 |

**按内容分块**：固定长度把相关信息切散时：
- 按文档的自然边界切（章节、段落、步骤）。
- 给分块补上下文：嵌入前在每个分块前面加上文档标题和章节标题。

### 评生成质量

确认检索没问题后，评模型怎么用检索到的资料，两个维度：

**忠实度**：输出是否准确反映了资料？查：
- **幻觉**：资料里没有的信息。在 RAG 里，哪怕是模型自己知道的正确事实，只要资料里没有，也算幻觉。
- **遗漏**：资料里相关的信息被忽略了。
- **曲解**：资料里的信息被表达错了。

**相关性**：输出有没有回答原问题？一个回答可能完全忠实于资料，却没回答用户问的。

用错误分析找出这个系统具体会怎么错：什么样的信息容易被编造、哪些约束容易被漏掉。

#### 按指标组合诊断

| 资料相关性 | 忠实度 | 回答相关性 | 诊断 |
|---|---|---|---|
| 高 | 高 | 低 | 文档对了，但生成时看错了段落 |
| 高 | 低 | -- | 对检索内容产生幻觉或曲解 |
| 低 | -- | -- | 检索问题，去修分块、embedding 或查询预处理 |

### 多跳检索评测

需要多个分块的信息才能回答的问题：

**两跳 Recall@k**：两跳问题里，两个标准分块都出现在前 k 个结果中的比例。

```
TwoHopRecall@k = (1/N) * sum(1 if {分块1, 分块2} ⊆ 前k个结果)
```

失败时归类：第一跳漏了、第二跳漏了、还是排名掉出了前 k。

## 反模式

- 只用一个端到端正确率，不分开测检索和生成。
- 不看轨迹直接上指标。
- 对合成评测数据过拟合。要定期用真实用户问题验证。
- 用相似度指标（ROUGE、BERTScore、余弦相似度）当生成评测的主指标。应该用基于错误分析的二元评估。
- 评生成却不检查它是否基于资料。
