# 调研综合

> 改编自 [anthropics/knowledge-work-plugins](https://github.com/anthropics/knowledge-work-plugins) 产品管理插件的 `synthesize-research`（Apache-2.0，Anthropic）。改动：中文化；去掉对 Claude 连接器的依赖；加入拾阶的证据标签；精简部分重复内容。本文件相对原文有修改。

把多个来源的用户研究综合成结构化洞察和建议。

## 流程

### 1. 收集输入

接受任意组合：用户粘贴的访谈记录、转写稿、问卷结果、反馈；上传的文档和表格。有文件读取或搜索工具就主动去找相关的调研文档。

先问清：
- 是什么类型的研究？（访谈、问卷、可用性测试、行为数据、客服工单、销售记录）
- 多少个来源 / 受访者？
- 有没有要验证的具体问题或假设？
- 结论要支撑什么决定？

### 2. 逐份提取

每个来源提取：
- **关键观察**：用户说了什么、做了什么、经历了什么。
- **原话**：能说明问题的逐字引语。
- **行为**：用户实际做了什么（和他说的对照）。
- **痛点**：不满、变通办法、没被满足的需求。
- **正面信号**：好用的地方、惊喜时刻。
- **背景**：用户类型、使用场景、熟练程度。

### 3. 找主题和规律

用主题分析（见下文方法），把观察归成主题，数清每个主题有几位受访者提到，评估影响多大，标出矛盾和意外。

做一张优先级矩阵：
- **高频 + 高影响**：最优先的发现。
- **低频 + 高影响**：对特定人群很重要。
- **高频 + 低影响**：体验优化项。
- **低频 + 低影响**：记下来，不优先。

### 4. 写综合报告

#### 研究概况
- 方法：做了哪些研究，多少受访者 / 来源。
- 研究问题：想弄清什么。
- 时间：什么时候做的。

#### 关键发现（5–8 条）
每条包括：
- **发现**：一句话说清洞察。
- **证据**：原话、数据或观察，注明来源和证据标签。
- **频率**：多少受访者 / 来源支持。
- **影响**：对体验或业务的影响有多大。
- **置信度**：高（证据充分）/ 中（有迹象）/ 低（早期信号）。

按"频率 × 影响"排序。

#### 用户分群 / 画像
研究里出现明显不同的人群时：名字和描述、关键特征和行为、独特需求和痛点、规模估计（有数据才写）。

#### 机会点
哪些需求没被满足、现有方案哪里不够、什么新能力能创造价值，按潜在影响排序。

#### 建议
做什么、改什么、还要深挖什么。每条都要能追回到具体发现，按影响和可行性排序。

#### 未解答的问题
研究没回答的、需要继续调查的、建议用什么方法补。

### 5. 回看和延伸

写完后问用户：哪条发现要展开或换个说法；要不要生成画像文档、机会地图、汇报材料；要不要给未解答的问题设计后续研究。

## 证据标签

每条证据都带标签，决定它能不能当决策依据：

| 标签 | 含义 | 能否当依据 |
|---|---|---|
| 【用户原话】 | 真实访谈 / 问卷原文，注明谁、何时 | 能 |
| 【行为数据】 | 埋点、日志等真实行为 | 能 |
| 【业务方表达】 | 业务方、老板、同事的说法 | 只能当线索 |
| 【模拟】 | AI 模拟的访谈或数据 | 不能，只能用来提假设 |
| 【AI 推断】 | 你根据材料做的推理 | 不能单独成立，要配验证计划 |

## 方法

### 主题分析
1. **通读**：先把所有材料过一遍，别急着打标签。
2. **初始编码**：逐条给观察、引语、数据点打描述性标签。标签宁多勿少，合并比拆分容易。
3. **形成主题**：把相关标签归成候选主题。
4. **检查主题**：每个主题证据够不够？主题之间是否分得开？连起来能不能讲通？
5. **命名**：给每个主题起清楚的名字，配一两句说明。
6. **成文**：把主题写成带证据的发现。

### 亲和图
1. 每条观察单独记一张便签。
2. 按相似度归堆，不预设类别。
3. 给每堆起名。
4. 堆多了再往上归一层。
5. 堆和堆之间的关系就是主题。

要点：一张便签只写一个洞察；归类可以反复挪；一堆太大多半混了几个主题，拆开；离群的便签很有价值，别硬塞。

### 三角验证
- **方法三角**：同一个问题，不同方法（访谈 + 问卷 + 数据）。
- **来源三角**：同一种方法，不同人群。
- **时间三角**：同一现象，不同时间点。

多来源支持的发现远比单一来源可靠。来源打架时是好事，往往说明背后有不同人群。

## 访谈记录分析

- **区分行为和态度**：他做了什么 vs 他怎么想。记下何时、何地、和谁、多频繁。
- **变通办法就是伪装起来的需求**，要标出来。
- **原话是证据，不是发现**。发现是你对原话的解读。引语按人群标注（「200 人团队的管理员」），不写真名。
- **说的不如做的**：用户说想要 X，但他的流程显示从不用类似功能，就把矛盾记下来。
- **强度信号**：情绪化的措辞、遇到的频率、变通花的力气、出错的后果。

跨访谈分析：哪些观察在多人身上出现、各主题被多少人提到、不同类型用户是否有不同模式、哪里有分歧（常常意味着分群）、什么推翻了你原来的假设。

## 问卷数据

**定量**：样本有没有代表性；看分布不只看均值（一半人打 1 一半人打 5，和所有人打 3 是两回事）；按人群拆开看；小样本别从小差异下结论。

**开放题**：当成迷你访谈处理，打标签、数频次、摘代表性原话。开放题里冒出、结构化题目没覆盖的主题，就是你没想到要问的。

**常见错误**：只报均值不报分布；忽略没回答的人；把 0.1 分的 NPS 变化当信号；把李克特量表当等距数据；把交叉表里的相关当因果。

## 定性和定量结合

- 定性先行：访谈揭示**发生了什么、为什么**，产出假设。
- 定量验证：问卷和数据回答**有多少人、多严重**。
- 再回到定性：解释意外的数字。

两者打架时：先查是不是测的人群不同、说的和做的不一样、问卷题目是不是没测到你以为的东西。如实报告分歧，继续调查，不要挑一个信。

## 画像

画像必须从研究数据里长出来，不靠想象：找行为聚类 → 定区分变量（公司规模、熟练度、使用频率、主要场景）→ 写画像 → 能用数据估算规模最好。

```
[画像名] —— [一句话描述]

是谁：角色、公司类型/规模、经验；怎么开始用这个产品的
想完成什么：主要目标和要完成的任务；怎么衡量成功
怎么用：频率和深度、关键流程、搭配的其他工具
主要痛点：前三个不满或未满足需求；已有的变通办法
看重什么：选方案最看重的；什么会让他换掉或流失
代表性原话：2–3 句
```

常见错误：按人口属性分画像（行为比年龄性别更能预测需求）；画像太多（3–5 个最合适）；凭空编；从不更新；画像不改变任何产品决策。

## 机会大小

每个机会估：受影响用户数、遇到频率、严重程度、付费或留存意愿。影响分 = 用户数 × 频率 × 严重度，再看证据强度、战略契合、可行性。

写法：亮出算式（「按工单量，每月约 2000 用户遇到；访谈显示其中约 60% 认为是严重阻碍」）；用区间不用假精确（「每月 1500–2500 人」）；机会之间做相对排序。

## 输出要求

- 标题清楚，结构分明；每条发现单独读也能看懂。
- 让数据说话，不硬套预设结论。
- 原话多引，按人群标注。
- 置信度写明白：两次访谈得出的是假设，不是结论。
- 建议要具体到能执行。「改进新手引导」不能执行，「在设置流程里加进度条」可以。
- 5–8 条强发现胜过 20 条弱发现。

在拾阶里，报告存为当前项目 `01-立项/` 下的 `调研综合-<主题>.md`，可作为立项第 02 站产物「用户画像与调研结论」的输入。
